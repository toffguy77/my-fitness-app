## Decisions

1. **Экранирование в `JsonLd`, а не на входе.** `JSON.stringify` с последующей
   заменой `<`→`<`, `>`→`>`, `&`→`&`, U+2028/U+2029 на
   escape-последовательности. Результат остаётся тем же JSON, а закрыть
   `<script>` из данных невозможно.
   *Отвергнуто:* чистить заголовки при сохранении статьи. Источников данных
   для разметки больше одного, и защита на выходе закрывает все сразу.

2. **404 только для адресов, которые не может открыть никто.** Slug, которого
   нет в публичном API, — `notFound()`. UUID, которого нет в публичном API,
   может быть статьёй для клиентов куратора, поэтому он рендерит клиентский
   просмотр с `noindex` (см. `seo-article-server-render`). Ошибка API (не 404)
   не превращается в 404: страница отдаёт ошибку `error.tsx`, а не ложное
   «не найдено».
   *Отвергнуто:* 404 для любого UUID вне публичного API. Тогда сломались бы
   ссылки на кураторские статьи из персональной ленты.

3. **Предел `limit` — 100, превышение обрезается, а не отклоняется.** Клиенты
   ленты просят 20; карта сайта обходит постранично (`seo-sitemap-at-request`).
   Обрезка совместима с любым существующим вызовом.
   *Отвергнуто:* `400` на превышение. Старый `limit=1000` карты сайта упал бы
   вместо того, чтобы вернуть первую сотню.

4. **`BreadcrumbList` из трёх элементов:** главная, «Статьи», статья.

5. **`app/content/loading.tsx` удаляется.** Он оборачивает сегмент статьи в
   Suspense: оболочка уходит со статусом 200 до того, как страница вызовет
   `notFound()`, и Next отдаёт «не найдено» с кодом 200 и мета-тегом `noindex`.
   Реальный 404 получается только без потоковой оболочки. Спиннер был нужен
   клиентской загрузке, которой после `seo-article-server-render` и
   `seo-feed-server-render` нет.
   *Отвергнуто:* полагаться на `noindex` при коде 200. Аудит смотрит на код
   ответа, и Вебмастер тоже.
   Проверка — только сборкой: модульный тест видит вызов `notFound()`, но не
   код ответа.
