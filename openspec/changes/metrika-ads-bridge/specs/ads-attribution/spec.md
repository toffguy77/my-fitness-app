## ADDED Requirements

### Requirement: Зеркалирование событий в счётчик по белому списку

Система SHALL отправлять в счётчик веб-аналитики достижение цели для продуктовых событий из объявленного белого списка и MUST NOT отправлять события вне его.

#### Scenario: Событие в белом списке

- **WHEN** регистрируется продуктовое событие, имя которого есть в белом списке
- **THEN** в счётчик отправляется достижение цели с этим именем
- **AND** событие также отправляется на собственную приёмку

#### Scenario: Событие вне белого списка

- **WHEN** регистрируется продуктовое событие, имени которого нет в белом списке
- **THEN** в счётчик ничего не отправляется

#### Scenario: Свойства события не передаются

- **WHEN** событие из белого списка регистрируется со свойствами
- **THEN** в счётчик передаётся только имя цели, без свойств

#### Scenario: Серверные события не зеркалируются из браузера

- **WHEN** белый список сверяется со словарём событий
- **THEN** ни одно событие, объявленное только для сервера, в белый список не входит

#### Scenario: Счётчик недоступен

- **WHEN** согласие на аналитические куки не дано или счётчик не загрузился
- **THEN** регистрация события не вызывает ошибки
- **AND** событие отправляется на собственную приёмку

#### Scenario: Белый список соответствует словарю

- **WHEN** имя в белом списке отсутствует в словаре продуктовых событий
- **THEN** проверка завершается ошибкой

### Requirement: Передача конверсий, случившихся вне браузера

Система SHALL передавать в счётчик события-факты, которые не происходят в браузере, задачей по расписанию, привязывая их к идентификатору браузера из заявки.

#### Scenario: Конверсия поставлена в очередь

- **WHEN** происходит событие-факт из объявленного набора передаваемых конверсий
- **THEN** конверсия ставится в очередь отправки с идентификатором браузера, именем и временем события

#### Scenario: Конверсия отправлена

- **WHEN** задача передачи конверсий находит неотправленную конверсию
- **THEN** конверсия загружается в счётчик
- **AND** отмечается как отправленная

#### Scenario: Повторный запуск не задваивает

- **WHEN** задача передачи конверсий запускается снова после успешной отправки
- **THEN** ранее отправленные конверсии не отправляются повторно

#### Scenario: Идентификатор браузера отсутствует

- **WHEN** происходит событие-факт, для которого идентификатор браузера неизвестен
- **THEN** конверсия в очередь не ставится

#### Scenario: Внешний сервис недоступен

- **WHEN** загрузка конверсий завершается ошибкой
- **THEN** конверсии остаются неотправленными и повторяются на следующем запуске
- **AND** событие-факт остаётся записанным в собственной аналитике

#### Scenario: Событие-факт не ждёт отправки

- **WHEN** происходит событие-факт
- **THEN** ответ пользователю не зависит от доступности внешнего сервиса

### Requirement: Способность выключается отсутствием доступа

Передача данных в счётчик SHALL быть необязательной способностью, выключаемой отсутствием токена доступа или номера счётчика.

#### Scenario: Доступ не настроен

- **WHEN** токен доступа или номер счётчика отсутствует в окружении
- **THEN** способность числится выключенной в ответе проверки состояния
- **AND** при старте выводится предупреждение с её именем
- **AND** задача передачи конверсий не регистрируется

#### Scenario: Доступ настроен

- **WHEN** токен доступа и номер счётчика заданы
- **THEN** способность числится включённой

### Requirement: Состав передаваемых наружу данных ограничен

Наружу MUST передаваться только имя цели, идентификатор браузера, идентификатор рекламного перехода, метки кампании и время события.

#### Scenario: Запрещённое поле в передаче

- **WHEN** в состав передаваемых наружу данных попадает поле из списка запрещённых свойств
- **THEN** проверка завершается ошибкой

#### Scenario: Состав объявлен

- **WHEN** тест сверяет состав передаваемых наружу данных с объявленным списком
- **THEN** несовпадение завершается ошибкой

### Requirement: Состав целей счётчика задаётся из репозитория

Приведение целей счётчика к объявленному списку SHALL выполняться скриптом, который по умолчанию не меняет состояние внешнего сервиса.

#### Scenario: Запуск без изменений

- **WHEN** скрипт запускается без явного указания применить изменения
- **THEN** он выводит расхождение между целями счётчика и объявленным списком
- **AND** не изменяет цели

#### Scenario: Применение изменений

- **WHEN** скрипт запускается с явным указанием применить изменения
- **THEN** отсутствующие цели создаются
- **AND** скрипт сообщает, что признак ретаргетинга выставляется не им

#### Scenario: Цель ещё не выбрана в Директе

- **WHEN** объявленная цель заведена, но не несёт признака ретаргетинга
- **THEN** скрипт называет её и не пытается изменить признак

#### Scenario: Повторное применение

- **WHEN** скрипт применяется повторно без изменения объявленного списка
- **THEN** цели не создаются заново и не дублируются

#### Scenario: Доступ не настроен

- **WHEN** скрипт запускается без токена доступа
- **THEN** он завершается с внятным сообщением и не пытается обратиться к внешнему сервису
