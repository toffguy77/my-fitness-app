# Проверка на стенде

Задачи 7.2 и 7.3, выполнены 2026-09-24 на локальном стенде через `dev-proxy`
на 3070, против базы `web-app-db-dev`.

## Найдено при проверке: миграции молча не применялись

Первый прогон вернул `500`, а в журнале было
`column "utm_source" of relation "leads" does not exist` — при том, что мигратор
при старте отчитался `Migrations: all up to date, applied: 75`.

Причина: **база dev впереди этой ветки**. В `schema_migrations` уже были записи

| версия | имя |
|---|---|
| 073 | `magic_links` |
| 074 | `email_verification_code_purpose` |
| 075 | `lead_conversation_index` |
| 076 | `support_channels` |
| 077 | `leads_capture_source` |

из работы, выкатанной на dev раньше. Файлов `_up.sql` в ветке 73, записей в
базе 75, максимум 77.

`loadPending` (`internal/shared/database/migrator.go:151`) сверяет **только
номер**: версия, уже записанная в `schema_migrations`, считается применённой
независимо от имени. Мои 073–075 совпали по номеру с чужими и были пропущены
без единого сообщения.

Миграции перенумерованы в **078, 079, 080** и применились:

```
Migrations: applying pending {"count": 3}
Migration applied {"version": 78, "name": "lead_attribution"}
Migration applied {"version": 79, "name": "user_attribution"}
Migration applied {"version": 80, "name": "conversion_uploads"}
```

Это было бы выкачено на прод молча сломанным: приложение поднялось бы, а
сохранение заявки отвечало бы `500`.

## Заявка с метками кампании (7.2)

```
POST /api/v1/public/leads → 201
источник в ответе: utm_source=yandex, utm_medium=cpc, utm_campaign=autumn,
                   utm_term=кбжу, yandex_click_id=yclid-проверка
```

Дозапись идентификатора браузера:

| вызов | ответ |
|---|---|
| первый, действующий токен | `{"recorded": true}` |
| повторный, другое значение | `{"recorded": true}`, значение **не изменилось** |
| чужой токен | `{"recorded": false}`, ни одна заявка не тронута |

Чтение заявки обратно: `metrika_client_id = cid-проверка-42` — то, что записано
первым, а не вторым.

В браузере: приход на `/onboarding?utm_source=…&utm_campaign=autumn&yclid=42`
кладёт метки в хранилище сеанса; после перехода строка запроса из адреса уходит,
а метки остаются — ради этого хранилище и заведено.

## Путь с заблокированным счётчиком (7.3)

Все запросы к `mc.yandex.*` отклонены на уровне браузера:

- заявка сохраняется: `201`;
- ошибок на странице — ни одной;
- идентификатора браузера у заявки нет, и это ожидаемо: контакт важнее
  атрибуции, которой в этом случае всё равно не было бы.
