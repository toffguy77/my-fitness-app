## ADDED Requirements

### Requirement: Тип файла определяется по содержимому

Сервер SHALL определять тип загружаемого файла по его содержимому. Значение заголовка `Content-Type`, присланное клиентом, MUST NOT использоваться ни для проверки допустимости, ни для сохранения объекта в хранилище.

#### Scenario: Несоответствие заголовка и содержимого

- **WHEN** клиент загружает файл с HTML-содержимым и заголовком `Content-Type: image/png`
- **THEN** API отвечает статусом `400`
- **AND** объект в хранилище не создаётся

#### Scenario: Корректное изображение

- **WHEN** клиент загружает файл с содержимым JPEG
- **THEN** файл принимается
- **AND** объект в хранилище сохраняется с типом содержимого, определённым по содержимому файла

#### Scenario: Файл без заголовка типа

- **WHEN** клиент загружает файл, не указав заголовок `Content-Type`
- **THEN** тип определяется по содержимому
- **AND** решение о приёме принимается по определённому типу

### Requirement: Белый список типов на каждой точке загрузки

Каждая точка загрузки SHALL принимать только типы файлов из явно заданного для неё списка. Аватар профиля, фото еды и фото прогресса MUST ограничиваться JPEG, PNG и WebP. Вложения чата MUST ограничиваться JPEG, PNG, WebP и PDF.

#### Scenario: Недопустимый тип во вложении чата

- **WHEN** пользователь загружает во вложение чата исполняемый файл
- **THEN** API отвечает статусом `400` с сообщением на русском языке, называющим допустимые форматы

#### Scenario: Документ в поле аватара

- **WHEN** пользователь загружает PDF в качестве аватара профиля
- **THEN** API отвечает статусом `400`

### Requirement: Пределы изображений

Изображения SHALL проверяться на предельные размеры до полной распаковки. Изображение с длиной любой стороны более 8000 пикселей или общей площадью более 50 мегапикселей MUST отклоняться.

#### Scenario: Изображение с чрезмерными размерами

- **WHEN** пользователь загружает корректное по формату изображение размером 30000 на 30000 пикселей
- **THEN** API отвечает статусом `400`
- **AND** полная распаковка изображения не выполняется

#### Scenario: Изображение в допустимых пределах

- **WHEN** пользователь загружает изображение 3000 на 2000 пикселей допустимого формата и размера
- **THEN** файл принимается

### Requirement: Удаление метаданных изображения

Принятые изображения SHALL сохраняться без метаданных исходного файла, включая данные о геопозиции.

#### Scenario: Изображение с геометкой

- **WHEN** пользователь загружает фотографию, содержащую координаты съёмки в метаданных
- **THEN** сохранённый в хранилище объект не содержит этих координат

### Requirement: Имя объекта не зависит от имени загруженного файла

Ключ объекта в хранилище SHALL формироваться сервером и содержать префикс раздела, идентификатор пользователя и случайный идентификатор. Присланное клиентом имя файла MUST NOT входить в ключ.

#### Scenario: Имя файла с обходом пути

- **WHEN** клиент загружает файл с именем, содержащим последовательности перехода по каталогам
- **THEN** созданный объект имеет ключ, сформированный сервером и не содержащий присланного имени

#### Scenario: Сохранение исходного имени для отображения

- **WHEN** загружается вложение чата с именем файла
- **THEN** исходное имя сохраняется отдельным полем записи вложения
- **AND** ключ объекта в хранилище его не содержит

### Requirement: Общий предел размера тела запроса

Сервер SHALL ограничивать размер тела любого запроса общим пределом на уровне middleware, превышающим максимальный допустимый размер загружаемого файла.

#### Scenario: Запрос с телом сверх общего предела

- **WHEN** клиент отправляет запрос с телом, превышающим общий предел
- **THEN** сервер отвечает статусом `413`
- **AND** обработчик маршрута не вызывается
