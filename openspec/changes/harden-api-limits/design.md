## Context

Все пять точек загрузки написаны независимо и валидируют по-разному: где-то `strings.HasPrefix(contentType, "image/")`, где-то ничего. Общего места, через которое проходит файл, нет — есть общий `S3Client.UploadFile`, но он принимает `contentType` параметром и доверяет вызывающему.

Часть бакетов публична (`UploadPublicFile` с ACL `public-read`) — там лежат медиа контента и, возможно, аватары. Публичный бакет с произвольным содержимым и произвольным `Content-Type` — это способ разместить активный контент на домене `storage.yandexcloud.net`. Он не совпадает с доменом приложения, поэтому прямой кражи сессии не даёт, но остаётся площадкой для фишинга от имени сервиса.

По спискам: `GetUsers` — единственный запрос без ограничения, который при этом делает полную агрегацию по растущей таблице токенов. Остальные списки ограничены естественно (клиенты одного куратора), но контракта нет, поэтому следующий список снова окажется неограниченным.

## Goals / Non-Goals

**Goals:**
- Содержимое файла определяет его тип, а не заголовок запроса.
- Ни одна точка загрузки не валидирует по-своему.
- Ни одна коллекция не отдаётся целиком.
- Пользователь получает понятную причину отказа.

**Non-Goals:**
- Не вводим антивирусную проверку загружаемого.
- Не переводим загрузки на прямую отдачу в S3 по предподписанной ссылке.
- Не меняем структуру бакетов и их публичность (отдельный вопрос).
- Не вводим курсорную пагинацию — для текущих объёмов достаточно `limit`/`offset`.

## Decisions

**Решение 1. Тип определяется по первым 512 байтам через `http.DetectContentType`, затем сверяется с белым списком точки загрузки.**
Заголовок `Content-Type` от клиента не используется ни для валидации, ни для сохранения в S3.
*Почему стандартная библиотека:* покрывает нужные форматы (JPEG, PNG, GIF, WebP, PDF), не добавляет зависимость.
*Ограничение:* `DetectContentType` не различает некоторые форматы тонко — для изображений дополнительно применяется `image.DecodeConfig`, который подтверждает, что это действительно декодируемое изображение, и заодно даёт размеры.
*Альтернатива:* доверять заголовку и только проверять префикс. Отвергнута — это текущее поведение и есть проблема.

**Решение 2. Белый список — свой на каждую точку загрузки.**
Аватар и фото еды — только JPEG, PNG, WebP. Фото прогресса — то же. Медиа контента — плюс GIF. Вложения чата — плюс PDF.
*Почему не один общий список:* вложение чата и аватар имеют разный профиль риска и разные ожидания пользователя.

**Решение 3. Предел размеров изображения в пикселях, а не только в байтах.**
`image.DecodeConfig` читает заголовок изображения без полной распаковки и даёт ширину и высоту. Отклоняем более 8000 пикселей по любой стороне и более 50 мегапикселей суммарно.
*Почему так:* байтовый предел не защищает от сильно сжатого огромного изображения — распаковка 30000×30000 требует гигабайтов памяти.
*Альтернатива:* полагаться на предел в байтах. Отвергнута по причине выше.

**Решение 4. Изображения перекодируются, метаданные удаляются.**
Изображение декодируется и кодируется заново в тот же формат. Побочный эффект — EXIF, включая GPS-координаты, не попадает в хранилище.
*Почему это важно именно здесь:* фотографии прогресса — снимки тела, сделанные дома. Координаты дома в публичном бакете недопустимы.
*Стоимость:* процессорное время на загрузку. Приемлемо: загрузки редкие, размеры ограничены.
*Альтернатива:* вырезать только EXIF. Отвергнута: перекодирование заодно гарантирует, что файл действительно является изображением, а не полиглотом.

**Решение 5. Ключ объекта в S3 не содержит присланного имени файла.**
Формат: `<префикс>/<user_id>/<uuid>.<расширение из определённого типа>`. Оригинальное имя, если нужно показать пользователю, хранится отдельным полем в БД.
*Почему так:* убирает обход путей и внедрение управляющих символов в ключ; сохраняет требуемый изменением `account-deletion-and-data-export` префикс с идентификатором пользователя.

**Решение 6. Постраничная выдача — `limit`/`offset` с предельным `limit` и полем `total`.**
Ответ коллекции: `{ items, total, limit, offset }`. Значение по умолчанию 20, предел 100. Значение выше предела не отклоняется, а понижается до предела.
*Почему понижение, а не ошибка:* клиент, попросивший 1000, получает 100 и поле `total` — этого достаточно, чтобы продолжить; ошибка ломала бы существующие вызовы.
*Альтернатива:* курсорная пагинация. Отвергнута: сложнее, а объёмы не требуют; при росте переход возможен без изменения формы ответа.

**Решение 7. `GetUsers` дополнительно переписывается, а не только ограничивается.**
Подзапрос `MAX(created_at) FROM refresh_tokens GROUP BY user_id` агрегирует всю таблицу независимо от `LIMIT`. Он выносится в отдельный запрос по идентификаторам страницы — как уже сделано в кураторском модуле (`curator/service.go` собирает данные по списку идентификаторов отдельными запросами).
*Почему так:* один только `LIMIT` не убрал бы полную агрегацию.

**Решение 8. Общий предел тела запроса — middleware, а не проверка в хендлере.**
`http.MaxBytesReader` на весь роутер с пределом 12 МБ, чтобы вместить самую большую разрешённую загрузку с запасом; точечные пределы остаются в хендлерах.
*Почему так:* защищает и те эндпоинты, которые про размер тела не думали.

## Risks / Trade-offs

- **Риск: перекодирование изменит вид изображений** (потеря качества при повторном JPEG). → Кодировать с высоким качеством; для PNG перекодирование без потерь.
- **Риск: отклонение ранее принимавшихся файлов** (например, HEIC с iPhone). → Проверить на dev, какие форматы реально приходят; при необходимости добавить HEIC в белый список с конвертацией или дать явное сообщение «сохраните как JPEG».
- **Риск: постраничная выдача ломает существующие экраны,** ожидающие массив. → Формат ответа меняется одновременно на бэкенде и фронтенде в одном изменении; затронутые экраны перечислены в задачах.
- **Риск: `MaxBytesReader` обрежет легитимную большую загрузку.** → Предел выше максимального точечного; тест на границе.
- **Trade-off: `limit`/`offset` даёт нестабильную выдачу** при активной вставке. Для админских списков приемлемо.

## Migration Plan

1. Пакет `upload`, перевод точек загрузки, выкатка на dev, проверка всех пяти сценариев загрузки.
2. Формат ответа коллекции и middleware предела тела.
3. Перевод `GetUsers` и `GetConversations` вместе с их экранами.
4. Проверка на проде на реальных объёмах.

**Откат:** возврат образа; изменений схемы БД нет, кроме поля оригинального имени файла (аддитивное).
