## Why

Два класса проблем на границе API, каждый из которых сейчас держится на удаче.

**Загрузки принимаются по слову клиента.** Тип содержимого берётся из заголовка `Content-Type`, который присылает сам загружающий: `apps/api/internal/modules/users/handler.go:234-235` (аватар), `apps/api/internal/modules/food-tracker/handler.go:379-380` (фото еды), `apps/api/internal/modules/dashboard/handler.go:583` (фото прогресса). В чате ещё мягче — `apps/api/internal/modules/chat/handler.go:224-226` подставляет `application/octet-stream`, если заголовка нет, и грузит что угодно. Файл затем кладётся в S3 с этим же `Content-Type` (`internal/shared/storage/s3.go:115`), а часть бакетов отдаётся публично (`UploadPublicFile`, `s3.go:104`). Загруженный HTML с заголовком `image/png` попадёт в бакет как HTML — это хранимая XSS на домене хранилища. Кроме того, изображения принимаются без проверки размеров: «зип-бомба» в виде PNG 30000×30000 положит любой последующий обработчик.

**Списки отдаются целиком.** `apps/api/internal/modules/admin/service.go:39-67` — `GetUsers` без `LIMIT` и `OFFSET`, с тремя соединениями, включая полную агрегацию `MAX(created_at)` по всей таблице `refresh_tokens`. С ростом базы запрос деградирует линейно, а админский интерфейс пытается отрисовать всех пользователей разом. Аналогично не ограничены выдачи в `admin.GetConversations` и ряде кураторских списков.

## What Changes

- Тип загружаемого файла определяется по содержимому (сигнатуре), а не по заголовку запроса; заголовок клиента игнорируется при сохранении в S3.
- Вводится белый список допустимых типов на каждую точку загрузки; вложения чата ограничиваются изображениями и PDF вместо «чего угодно».
- Изображения проверяются на предельные размеры в пикселях и приводятся к безопасному виду; метаданные EXIF, включая геопозицию, удаляются.
- Имена объектов в S3 перестают зависеть от присланного имени файла; расширение выводится из определённого типа.
- Вводится единый формат постраничной выдачи для всех коллекций: параметры `limit` и `offset`, предельное значение `limit`, поле общего количества.
- `admin.GetUsers`, `admin.GetConversations` и неограниченные кураторские списки переводятся на постраничную выдачу; интерфейсы получают подгрузку.
- Вводится общий предел размера тела запроса и предел времени чтения тела на уровне middleware.

## Capabilities

### New Capabilities

- `upload-safety`: правила приёма файлов — определение типа, белые списки, пределы, обработка изображений, именование объектов.
- `collection-pagination`: единый контракт постраничной выдачи коллекций и запрет неограниченных выборок.

## Impact

**Бэкенд:**
- Новый пакет `apps/api/internal/shared/upload/` — определение типа по сигнатуре, валидация, обработка изображений.
- `internal/modules/users/handler.go:230-250`, `food-tracker/handler.go:375-420`, `dashboard/handler.go:575-600`, `chat/handler.go:218-245`, `content/handler.go` — переход на общий пакет.
- `internal/shared/storage/s3.go:98-140` — тип содержимого только из определённого, ключ без пользовательского имени.
- `internal/modules/admin/service.go:39-67` и handler — постраничная выдача.
- `internal/shared/response/` — формат ответа коллекции.
- Новый `internal/shared/middleware/bodylimit.go`.

**Фронтенд:**
- `apps/web/src/features/admin/` — подгрузка списков.
- Компоненты загрузки — сообщения об отклонённых типах и размерах.

**Зависимости:** стандартные `net/http.DetectContentType`, `image` из стандартной библиотеки; при необходимости декодирования размеров без полной распаковки — `image.DecodeConfig`.

**Порядок:** после `fix-authorization-gaps` (общие правки в хендлерах и роутере).
