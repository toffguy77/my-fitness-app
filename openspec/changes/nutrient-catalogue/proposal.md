## Why

`nutrient_recommendations` — справочник нутриентов с суточными нормами — **пуст
и на dev, и на проде**. Таблицу создала миграция 009
(`009_create_food_tracker_supporting_tables_up.sql`), а `INSERT` в неё нет ни в
одной миграции, ни в `seed.sql`, ни в засеве где-либо ещё. Проверено запросом в
обеих средах: ноль строк.

Найдено при работе над `unreachable-routes`: настоящий ответ
`GET /api/v1/food-tracker/recommendations` для человека с 47 записями о еде —

```json
{ "daily": { "fiber": [], "lipids": [], "minerals": [], "plant": [], "vitamins": [] },
  "weekly": null, "custom": null }
```

Под справочник уже написано всё остальное: четыре обработчика, запрос с
подсчётом потребления (`service.go:1752`), таблица предпочтений
`user_nutrient_preferences`, вкладка на 321 строку с тремя файлами тестов.
`unreachable-routes` соединяет половины — и вкладка всё равно остаётся пустой,
потому что показывать нечего.

**Почему это отдельное изменение, а не часть того.** Строки справочника — это
суточные нормы витаминов и минералов: сколько мг магния в день, сколько мкг B12,
при каких значениях считать норму достигнутой. Медицинские референсные значения
в продукте о здоровье, которые человек увидит рядом со своим весом и калориями.
Придумать их при реализации означало бы выдать выдумку за рекомендацию по
питанию. Механика — название, единица, категория — вопрос инженерный; цифры нет.

## What Changes

- Выбирается и **называется в коде** источник норм: чьи рекомендации берутся.
- Справочник наполняется по этому источнику, с указанием источника у каждой
  строки.
- Наполнение приходит миграцией, а не засевом: справочник нужен в каждой среде
  одинаковым, и среда без него отдаёт пустую вкладку.
- Появляется проверка, не дающая справочнику снова оказаться пустым.

## Capabilities

### New Capabilities

- `nutrient-catalogue`: состав справочника нутриентов, происхождение норм и
  требование непустоты.

## Open Decision

**Источник норм не выбран, и выбрать его должен человек, а не реализация.**

Варианты, которые встречаются в RU-продуктах:

- **Методические рекомендации МР 2.3.1.0253-21** (Роспотребнадзор) — нормы
  физиологических потребностей для населения России. Ближе всего к аудитории,
  на русском, ссылаемы.
- **EFSA Dietary Reference Values** — европейские, подробнее по группам,
  на английском.
Проверено: своего источника в продукте нет. `internal/modules/nutrition-calc`
считает КБЖУ формулой от параметров тела (`RecalculateForDate`) и никаких
референсных таблиц по витаминам и минералам не содержит — то есть выбор делается
с нуля, а не согласуется с уже принятым.

Ответ определяет не только цифры: от него зависит, нужны ли отдельные нормы по
полу и возрасту. Сейчас справочник этого не предусматривает — `daily_target`
одно число на нутриент, без разбиения. Если выбранный источник даёт нормы по
группам, потребуется миграция схемы, и объём изменения вырастает заметно.

**До ответа на этот вопрос браться не за что.** Задачи ниже описывают работу,
которая следует из любого ответа; те, что зависят от выбора, помечены.

## Impact

**Бэкенд:**
- Новая миграция — наполнение `nutrient_recommendations`.
- `internal/modules/food-tracker/` — проверка непустоты справочника.
- Возможна миграция схемы, если нормы окажутся зависящими от пола и возраста.

**Зависимости:** нет технических. Есть одна содержательная — выбор источника.

**Порядок:** после `unreachable-routes`. Наполнять справочник, к которому
вкладка не подключена, значит не увидеть результат.
