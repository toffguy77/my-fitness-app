# Разбор маршрутов без вызова из фронтенда

Задача 1.1. Снято 2026-09-26 по `internal/router/testdata/routes.golden` (164
маршрута).

**Первая оценка была неверной, и это выяснилось при написании проверки.** Ручной
разбор с сопоставлением, понимающим базовые константы, дал 8 маршрутов без
вызова. Написанная проверка дала 42. Разница — три формы записи пути, которых не
видел ни ручной разбор, ни скан:

| форма | пример | сколько скрывала |
|---|---|---|
| помощник, дописывающий префикс версии | `getApiUrl('/food-tracker/entries')` | 29 маршрутов, 40 вызовов в 10 файлах |
| склейка плюсом | `getApiUrl('/dashboard/tasks/' + id + '/complete')` | 2 |
| параметр перед строкой запроса | `` `${BASE}/clients/${id}?days=${n}` `` | 1 |

Итого 32 ложных обвинения из 42. После разбора всех трёх форм осталось 10
маршрутов, и каждый проверен глазами. Для прямой проверки невидимый путь — это
пропущенная проверка; для обратной — ложное обвинение, а проверку, которая врёт,
начинают обходить. Поэтому разбор форм записи не удобство, а условие
работоспособности.

## Законные — уходят в реестр

| маршрут | почему из браузера не зовут |
|---|---|
| `GET /health` | Проверка живости. Зовут Traefik и Dokploy, не приложение. |
| `GET /ready` | Проверка готовности, тот же вызывающий. |
| `GET /ws` | Открывается как WebSocket (`WebSocketProvider.tsx:71` собирает адрес из протокола и хоста), поэтому литерала `/api/...` в коде нет. |
| `GET /api/v1/auth/oauth/:provider/callback` | Сюда браузер приводит внешний провайдер; адрес знает он, а не наш код. |
| `POST /api/v1/public/support/telegram` | Вебхук Telegram. Зовёт Telegram, подлинность проверяется заголовком `X-Telegram-Bot-Api-Secret-Token`. |
| `GET /api/v1/public/leads/unsubscribe` | Ссылка из письма: открывают из почты, не со страницы. |
| `GET /api/v1/logs/stats` | Сводка журналов, только `super_admin` (`users.go:83`). Читается при разборе, интерфейса под неё нет и не планировался. |

Семь вместо трёх: `/ready`, `/ws`, обратный вызов внешнего провайдера и ссылка из
письма в первый разбор просто не попали — он смотрел только пути под `/api/v1`,
которые зовут из браузера запросом.

## Дефекты, найденные самой проверкой — уходят в `server-only-features`

Их ручной разбор не нашёл: они были среди 42 вместе с ложными.

| маршрут | что не так |
|---|---|
| `POST /api/v1/food-tracker/favorites/:foodId` | Добавить в избранное из интерфейса нельзя — кнопки нет. |
| `DELETE /api/v1/food-tracker/favorites/:foodId` | Убрать тоже неоткуда. |
| `POST /api/v1/content/articles/upload` | Загрузка статьи markdown-файлом (`UploadMarkdownFile`); в редакторе такой возможности нет. |

Избранное при этом показывается: `GET /food-tracker/favorites` зовут
(`useFoodSearch.ts:285`), список уходит в `SearchTab` как `popularFoods`. То
есть человек видит раздел, который всегда пуст, — тот же вид дефекта, что
справочник нутриентов без строк.

## Дефекты — закрывает это изменение

| маршрут | что не так |
|---|---|
| `GET /api/v1/food-tracker/recommendations` | Вкладка есть, смонтирована без пропсов. |
| `GET /api/v1/food-tracker/recommendations/:id` | Подробности нутриента не открываются ниоткуда. |
| `POST /api/v1/food-tracker/recommendations/custom` | `AddCustomRecommendationForm` есть, к серверу не подключена. |
| `PUT /api/v1/food-tracker/recommendations/preferences` | Настройка отслеживания не подключена; вдобавок `is_tracked` не отдаётся в ответе, так что текущее состояние всё равно было бы неизвестно. |
| `GET /api/v1/users/me/curator-group` | Ссылка в рабочую группу. Комментарий обработчика: «единственное место, где ссылку можно увидеть, это профиль». В профиле её нет. |

## Как это выглядело со стороны

Ни один сторож не возражал:

- `check-api-contract.mjs` проверяет обратное направление — что путь, который
  зовёт фронтенд, есть на сервере.
- TypeScript молчит: все восемь пропсов `RecommendationsTab` необязательные.
- Тесты проходят: они передают компоненту данные сами.
- Линтер молчит: неиспользуемого кода нет, компонент смонтирован.

Клиент видел пустую вкладку. Со стороны отчётов это неотличимо от «функцией не
пользуются».
