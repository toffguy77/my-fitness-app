# Проверка в браузере

Задача 8.2–8.3. Снято 2026-09-26 на локальном стенде (`make dev`, база dev),
через `dev-proxy` на **3070** — напрямую на 3069 сессии нет, `rewrite` в Next не
пробрасывает `Set-Cookie`.

Учётная запись — служебная `e2e-client@burcev.test` (id 45) из базы dev. Живые
аккаунты не использовались.

## До

```tsx
{activeTab === 'recommendations' && (
    <RecommendationsTab />
)}
```

Ни одного пропса, ни одного запроса: вызова `/food-tracker/recommendations` в
`apps/web` не существовало вовсе.

## После

Открытие вкладки «Рекомендации» в настоящем браузере:

```
GET /api/v1/food-tracker/recommendations -> 200
```

Содержимое вкладки:

```
Рекомендации
Настроить список
ДНЕВНЫЕ РЕКОМЕНДАЦИИ

Нормы по нутриентам пока не заведены, поэтому показывать нечего.

ПОЛЬЗОВАТЕЛЬСКИЕ

Нет пользовательских рекомендаций

Добавить рекомендацию
```

То есть запрос уходит, ответ разбирается без ошибок, и пустота названа своей
причиной — справочник `nutrient_recommendations` пуст (изменение
`nutrient-catalogue`). Раньше на этом месте было «Нет дневных рекомендаций» со
ссылкой на настройки, то есть предложение починить настройками то, что ими не
чинится.

## Чего эта проверка не покрыла

- **Непустой справочник.** Показать нутриенты негде, пока `nutrient-catalogue`
  не выполнено. Экран настроек, подробности по нутриенту и своя рекомендация
  проверены тестами, а в браузере — только тем, что открываются без ошибок.
- **Ссылка в рабочую группу.** Нужен куратор без привязанного Telegram;
  проверена тестами (`SettingsTelegram.test.tsx`), в браузере — нет.
- **Посторонние отказы.** На той же странице `401` отвечали
  `/dashboard/*`, `/notifications/*` и `/conversations/unread`. Это следствие
  того, как я входил: вход выполнялся запросом к API, а эти места
  аутентифицируются заголовком `Authorization`, который страница добывает сама
  при входе через форму. Маршруты рекомендаций в той же сессии отвечали `200`,
  потому что идут через `apiClient` с cookie. К изменению отношения не имеет,
  но и «прогон был чистый» сказать нельзя.
