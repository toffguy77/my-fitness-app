## Context

В вебе к моменту iOS уже решены вопросы, которые приложение должно
повторить, а не изобрести заново:

- **Значения дизайна.** Только в `packages/design-tokens/tokens/*.json`.
  Сборка проверяет паритет тем и контраст. В разметке — роли.
- **Ошибки.** Показываются по `code` (спека `localization`), а не по `message`
  сервера.
- **Повторы запросов.** Одинаковые GET в полёте объединяются (`apiClient.get`).
  Запросы, ушедшие до обновления сессии, ждут одно обновление
  (`api-client-first-request.test.ts`).
- **Роль.** Берётся из ответа сервера, а не из локального хранилища
  (`role-aware-shell`).

Ограничения стека:
- SwiftUI, iOS 18+;
- нативный вход и сессия — из `ios-native-session`;
- пуши — из `ios-push-notifications`.

## Goals / Non-Goals

**Goals:**
- Цвет или отступ меняется в одном JSON и одинаково приходит в веб и в iOS.
- Ни один экран не обращается к сети, Keychain или навигации в обход общих модулей.
- Изменение, сделанное без сети, не теряется и не задваивается.

**Non-Goals:**
- Android и общий кроссплатформенный код.
- Офлайн-режим для куратора с записью: куратор работает онлайн, кэш — только на чтение. Исключение — ответ из пуша: он идёт через очередь, чтобы пережить обрыв сети в момент отправки.
- Английская локализация в первой версии (строки сразу в String Catalog, перевод — позже).

## Decisions

### XcodeGen, а не закоммиченный `.xcodeproj`

`project.yml` — источник проекта. `.xcodeproj` генерируется и в git не
хранится.

Отвергнуто:
- **`.xcodeproj` в git.** Конфликты `project.pbxproj` при каждом
  добавлении файла, которые невозможно ревьюить.
- **Tuist.** Мощнее, но тянет свой рантайм и кэш. Для одного приложения с
  одним расширением XcodeGen достаточно.

### Токены: сгенерированный Swift и каталог цветов

`build.mjs` выпускает два файла.

1. `dist/ios/Colors.xcassets` — по colorset на роль (`bg.canvas` → `BgCanvas`)
   с вариантами Any и Dark. Цвет переключается системой без кода, работает в
   виджетах и на экране блокировки.
2. `dist/ios/Tokens.swift`:
   - `enum DS.Color` со ссылками на каталог;
   - `DS.Space`, `DS.Radius`, `DS.Size` (`CGFloat`);
   - `DS.Typography`: семейство, размер, межстрочный, вес, относительный
     стиль Dynamic Type — `title-1` → `.title`, `body` → `.body`, `num-xl` → `.largeTitle`.

Приложение подключает `dist/ios` как ресурсы пакета `DesignSystem`.
Swiftlint-правило запрещает `Color(red:…)`, `Color(hex:)` и литералы `#…`
вне `DesignSystem`.

Отвергнуто:
- **Читать `tokens.json` во время работы приложения.** Ошибка в имени
  роли всплывает у пользователя, а не при компиляции. Виджеты и
  `Color` из каталога работают быстрее.
- **Style Dictionary.** Сборка токенов уже своя и проверяет контраст. Второй
  генератор с другими правилами разойдётся с первым.

### Шрифты бренда с Dynamic Type

Literata (заголовки) и Golos Text (текст и числа) встраиваются как
переменные шрифты (OFL). Используется
`Font.custom(name, size:, relativeTo:)`, поэтому размер следует настройке
«Размер текста».

Системные панели (таббар, навбар, листы) остаются на SF: их рисует система, и
на iOS 26 они получают Liquid Glass без кода.

Отвергнуто:
- **SF везде.** Приложение перестаёт быть похожим на веб и бренд.
- **Фиксированные размеры.** Недоступно для людей с крупным текстом, и
  ревью App Store обращает на это внимание.

### Одна очередь обновления сессии

`SessionStore` — actor.
- Первый запрос, получивший `401 token_expired`, запускает `native/refresh`.
- Остальные ждут ту же задачу.
- После успеха все повторяются с новым access-токеном.

Это важно не только для скорости. Два параллельных обновления одним токеном —
это повторное использование: сервер отзовёт все сессии пользователя.

Расширение виджетов не обновляет сессию само. Оно читает access-токен из
общей группы Keychain. Если токен просрочен, App Intent расширения кладёт
изменение в общую очередь (`Outbox` в App Group), и приложение досылает его
при следующем запуске или фоновом обновлении.

Отвергнуто:
- **Обновлять и в расширении.** Два процесса с одним refresh-токеном —
  гонка, которая кончается `session_ended`.

### Офлайн: кэш на чтение и очередь на запись

- **Кэш.** Последний ответ каждого экрана (день, неделя, лента, список
  переписок) хранится в SwiftData с меткой времени. Экран сначала
  показывает кэш с подписью «Обновлено в 14:20», затем свежие данные.
- **Очередь (`Outbox`).** Изменения хранятся в SQLite в App Group: запрос,
  `Idempotency-Key`, число попыток. Очередь досылается при:
  - появлении сети (`NWPathMonitor`);
  - выходе приложения на передний план;
  - фоновой задаче `BGAppRefreshTask`.

  Интерфейс применяет изменение оптимистично сразу.

Отвергнуто:
- **Офлайн только с кэшем, без очереди.** Запись еды в метро — главный
  сценарий дневника, отказ «нет сети» его ломает.
- **CoreData для очереди.** Очередь читают два процесса (приложение и
  расширение). Простая SQLite-таблица с блокировкой предсказуемее.

### `Idempotency-Key` на сервере

Middleware для перечисленных маршрутов работает так:
1. Ключ (UUID, заголовок `Idempotency-Key`) вместе с пользователем, методом
   и путём записывается в `idempotency_keys`, ответ сохраняется на 24 часа.
2. Повтор с тем же ключом и тем же телом возвращает сохранённый ответ с
   заголовком `Idempotent-Replayed: true`.
3. Повтор с тем же ключом и другим телом получает `422` с кодом `conflict`.
4. Без заголовка поведение прежнее — веб не меняется.

Отвергнуто:
- **Дедупликация по содержимому на клиенте.** Сеть рвётся после того,
  как сервер записал, но до ответа. Клиент не знает, записано ли.
- **Естественные ключи (клиентский id записи).** Пришлось бы менять схему
  каждой таблицы. Ключ запроса решает это в одном месте.

### Маршрутизатор ссылок

`Router` принимает:
- universal link (`/auth/link/consume`, `/reset-password`, `/content/<slug>`,
  `/dashboard?task=`, `/food-tracker?date=&add=`, `/chat`, `/notifications`,
  `/curator/clients/:id?tab=`, `/curator/chat/:id`, `/curator/support?conversation=`);
- `target` пуша;
- App Intent.

Всё это превращается в путь навигации текущей роли. Ссылка, не подходящая
роли (клиент открыл `/curator/...`), открывает корень роли. Ссылка до входа
запоминается и открывается после входа.

### Аналитика — только собственные события

Приложение отправляет события в тот же `POST /api/v1/public/analytics/events`, что веб. Сторонних SDK (Метрика, Firebase и т. п.) нет, данные с чужими не связываются — запрос App Tracking Transparency не нужен. В ярлыках приватности App Store события — «Данные об использовании», связанные с пользователем, не для отслеживания.

Отвергнуто:
- **AppMetrica / Firebase Analytics.** Сторонний получатель данных о здоровье и питании, ярлык «используется для отслеживания» и лишняя зависимость.

### CI на macOS — отдельная задача, не обязательная

Задача `ios`:
- `macos-15`, Xcode 26;
- `xcodegen generate`, `xcodebuild test` на симуляторе iPhone 16;
- запускается фильтром путей.

Имена обязательных проверок — договор (`CLAUDE.md`). Новая проверка
становится обязательной отдельным решением, когда приложение выйдет в
App Store.

## Risks / Trade-offs

- [Минуты macOS-раннеров дорогие] → фильтр путей; кэш DerivedData и SPM.
- [Шрифты увеличивают размер приложения] → только нужные начертания (переменный шрифт, ~600 КБ на семейство).
- [Кэш показывает устаревшие данные куратору] → у куратора кэш только для мгновенного первого кадра, рядом всегда видна метка «Обновлено …».

## Migration Plan

1. Сборка токенов с выводом для iOS. Веб не затронут. `tokens:check` проверяет новый вывод.
2. Middleware `Idempotency-Key` и миграция на бэкенде. Без заголовка ничего не меняется.
3. Каркас приложения: оболочка, вход, справочник компонентов — первая сборка TestFlight.
