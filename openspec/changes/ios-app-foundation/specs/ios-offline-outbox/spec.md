## ADDED Requirements

### Requirement: Экран показывает кэш, затем свежие данные

Экраны «Сегодня», «Дневник» (по дню), «Статьи» (лента по категории и открытые статьи), «Меню» (план дня), уведомления, переписка клиента с куратором (список и последние сообщения открытой переписки), а у куратора «Клиенты», «Чаты», переписка с клиентом и карточка клиента SHALL при открытии сразу показывать последний сохранённый ответ с подписью времени обновления, если он есть, и заменять его свежим ответом. Пока свежий ответ не пришёл, а сеть есть, экран MUST показывать только подпись «Обновлено в …», без плашки «Нет подключения». Если свежий ответ не получен из-за сети, экран SHALL оставлять сохранённый ответ с подписью и плашкой «Нет подключения», а не показывать ошибку. Кэш MUST принадлежать пользователю: ответ другого аккаунта на устройстве MUST NOT показываться, а выход MUST удалять кэш вместе с изображениями аккаунта. Кэш куратора — только на чтение: действия куратора выполняются онлайн и без сети завершаются понятным отказом, а введённое не теряется.

#### Scenario: Открытие без сети

- **WHEN** пользователь открывает «Дневник» без сети
- **THEN** показан сохранённый день с подписью «Обновлено в 14:20» и плашкой «Нет подключения»

#### Scenario: Нет сети и нет кэша

- **WHEN** экран открыт без сети, а сохранённого ответа нет (первый запуск, другой день, другой аккаунт)
- **THEN** показано состояние «Нет подключения» с объяснением, что экран обновится, когда появится сеть
- **AND** нет бесконечной загрузки и повторяющегося сообщения об ошибке

#### Scenario: Чужой кэш

- **WHEN** на устройстве остался кэш аккаунта А, а вошёл аккаунт Б
- **THEN** ни один экран не показывает данные аккаунта А

### Requirement: Быстрый запуск

Запуск с сохранённой сессией SHALL показывать оболочку роли по сохранённому профилю (роль, имя, часовой пояс, язык) и сохранённый день «Сегодня» без ожидания сети и без экрана загрузки, если кэш есть; свежие данные SHALL приходить в фоне и заменять показанные. До первого кадра оболочки приложение MUST NOT ждать ответов сервера.

#### Scenario: Запуск в метро

- **WHEN** клиент с сохранённой сессией запускает приложение без сети
- **THEN** сразу открыта оболочка клиента и «Сегодня» с сохранёнными данными и подписью «Обновлено в …»
- **AND** экрана «Загружаем профиль» нет

#### Scenario: Запуск с сетью

- **WHEN** клиент запускает приложение с сетью и кэш есть
- **THEN** сохранённый день показан сразу, а после ответа сервера заменён свежим без перезагрузки экрана

### Requirement: Изображения сохраняются на устройстве

Обложки статей, фото рецептов, аватары и фото переписки SHALL загружаться только с проверенных адресов и сохраняться на диске с ограничением размера, чтобы без сети показываться из сохранённого. Изображения аккаунта (аватары, фото переписки) MUST храниться в каталоге аккаунта и удаляться при выходе.

#### Scenario: Фото переписки без сети

- **WHEN** клиент открывает переписку без сети после того, как видел её с сетью
- **THEN** фото в переписке показаны из сохранённого

### Requirement: Изменения без сети ставятся в очередь и не теряются

Запись еды, правка и удаление записи, «Съел» в «Меню», вода, вес, шаги, тренировка, отметка задачи, сообщение чата и вложение переписки (загрузка файла, затем сообщение с его адресом) SHALL при отсутствии сети применяться в интерфейсе сразу и сохраняться в очереди, переживающей перезапуск приложения. Ответ 4xx, кроме `401`, `408`, `429` и `409` с заголовком `Retry-After` (тот же `Idempotency-Key` ещё выполняется на сервере, см. `idempotent-mutations`), MUST считаться окончательным отказом. Очередь MUST досылаться при появлении сети, выходе приложения на передний план и в фоновом обновлении, в порядке постановки, и только от имени вошедшего аккаунта: досылка до восстановления сессии MUST NOT удалять изменения. Окончательный отказ из любой досылки (в том числе фоновой и из виджета) SHALL откатывать оптимистичный результат на экране владельца изменения и показывать сообщение. Изменения, которым сеть нужна по сути (распознавание еды по фото, фото недели, создание своего продукта, настройки аккаунта, действия куратора), MUST без сети завершаться понятным сообщением, сохраняя введённое.

#### Scenario: Запись в метро

- **WHEN** без сети записан завтрак, приложение выгружено из памяти, затем появилась сеть и приложение открыто
- **THEN** запись отправлена на сервер и видна в вебе

#### Scenario: Фото в переписку без сети

- **WHEN** клиент без сети отправляет фото куратору
- **THEN** в переписке пузырь «ждёт отправки», он остаётся и после перезапуска
- **AND** при появлении сети файл загружается, затем отправляется сообщение с его адресом

#### Scenario: Досылка до восстановления сессии

- **WHEN** фоновая задача или тихий пуш запускает досылку раньше, чем приложение восстановило сессию
- **THEN** ни одно изменение не удалено из очереди

#### Scenario: Сервер отказал по существу

- **WHEN** досылаемое изменение получает ответ 4xx, кроме `401`, `408`, `429` и `409` с `Retry-After`
- **THEN** изменение снимается из очереди, оптимистичный результат откатывается
- **AND** показано сообщение по коду ошибки

### Requirement: Повтор не создаёт дублей

Каждое изменение очереди SHALL отправляться с заголовком `Idempotency-Key`, постоянным для всех попыток этого изменения.

#### Scenario: Ответ потерян после записи

- **WHEN** сервер записал еду, но ответ не дошёл, и очередь повторила запрос
- **THEN** в дневнике одна запись
