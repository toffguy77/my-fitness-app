## ADDED Requirements

### Requirement: Ответ разбирается из общего конверта

Клиент API SHALL разбирать ответы вида `{status, data, code, params, message}`: при `status = success` возвращать `data`, иначе — ошибку с `code`, `params` и HTTP-статусом. Ответ `204` MUST возвращаться как пустой успех.

#### Scenario: Ошибка с кодом

- **WHEN** сервер отвечает `429` с `{status: "error", code: "too_many_attempts"}`
- **THEN** вызов завершается ошибкой с кодом `too_many_attempts`

### Requirement: Тексты ошибок берутся по коду

Интерфейс SHALL показывать текст ошибки из каталога строк по `code` с подстановкой `params`; поле `message` сервера MUST NOT показываться пользователю. Для неизвестного кода MUST показываться общий текст по HTTP-статусу (сеть — «Проверьте подключение к интернету», 5xx — «Сервис временно недоступен»).

#### Scenario: Тест полноты каталога

- **WHEN** запускаются тесты пакета `API`
- **THEN** для каждого кода из `apps/api/internal/shared/apperrors/codes.go` в каталоге строк есть текст

### Requirement: Одно обновление сессии на параллельные запросы

При ответе `401` с кодом `token_expired` клиент SHALL выполнять ровно один `native/refresh` на все запросы, ожидающие в этот момент, и повторять каждый из них с новым access-токеном. Ответ `401` с кодом `session_ended` MUST завершать сессию без повтора.

#### Scenario: Три запроса с просроченным токеном

- **WHEN** три запроса одновременно получают `401 token_expired`
- **THEN** отправлен один запрос `native/refresh`
- **AND** все три запроса повторены и завершились успешно

#### Scenario: Сессия отозвана

- **WHEN** обновление отвечает `401 session_ended`
- **THEN** сессия удалена из Keychain и показан экран входа с текстом «Сессия завершена, войдите снова»

### Requirement: Язык запросов — язык профиля

Клиент API SHALL отправлять `Accept-Language` по языку профиля пользователя (`ru` или `en`), а до входа и без языка в профиле — `ru`.

#### Scenario: Язык профиля английский

- **WHEN** в профиле выбран английский
- **THEN** запросы уходят с `Accept-Language: en`

### Requirement: Одинаковые GET в полёте объединяются

Одновременные GET с одинаковым адресом SHALL обслуживаться одним сетевым запросом; каждый вызывающий MUST получать собственную копию результата.

#### Scenario: Оболочка и экран спрашивают профиль

- **WHEN** два компонента одновременно запрашивают `GET /auth/me`
- **THEN** по сети ушёл один запрос
