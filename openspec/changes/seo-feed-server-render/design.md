## Context

`FeedList` выбирает источник по сессии: вошедшему — `contentApi.getFeed` (видит
статьи своего куратора), гостю — `publicContentApi.getFeed`. Сессия на сервере
Next неизвестна: refresh-cookie ограничена путём `/api/v1/auth`.

## Goals / Non-Goals

**Goals:** ссылки на 20 последних публичных статей в HTML; без вспышки пустой
ленты у гостя.

**Non-Goals:** серверный рендер ленты вошедшего пользователя; серверная
пагинация через `?page=` (20 карточек и sitemap покрывают все 10 статей с
запасом; пагинация понадобится, когда статей станет больше страницы).

## Decisions

1. **Начальные данные — публичная лента без рубрики.** Сервер всегда отдаёт
   публичную ленту. Гость видит её сразу и повторно не запрашивает. Вошедший
   видит её до ответа своей ленты, затем она заменяется его лентой.
   *Отвергнуто:* не рендерить начальные данные для вошедшего. Сервер не знает,
   вошёл ли человек, а это и есть единственный вариант, при котором HTML
   одинаков для робота и гостя.

2. **Пропуск первого запроса гостя определяется совпадением ключа.** `FeedList`
   помнит, для какой пары «рубрика + источник» получены начальные данные
   (`null` + публичный), и не запрашивает её повторно.
   *Отвергнуто:* флаг «первый рендер». С React Compiler и строгим режимом эффект
   выполняется дважды, и флаг в ref ведёт себя хрупко.

3. **Ошибка сервера — пустые начальные данные.** Если API на сервере недоступен,
   страница рендерится без карточек, и `FeedList` загружает их сам, как раньше.

## Risks / Trade-offs

- Вошедший на мгновение видит публичную ленту вместо своей → она является
  подмножеством его ленты, вспышки чужого содержимого нет.
