## ADDED Requirements

### Requirement: Ошибки API не привязаны к языку

Тело ответа об ошибке SHALL содержать машиночитаемый код ошибки и, при необходимости, параметры для подстановки. Клиент MUST формировать отображаемое сообщение по коду. Сервер MUST NOT требовать от клиента показывать присланный им текст.

#### Scenario: Отказ в доступе к чату

- **WHEN** пользователь обращается к чужому чату
- **THEN** тело ответа содержит код ошибки, однозначно обозначающий отказ в доступе к чату
- **AND** клиент отображает сообщение, найденное по этому коду в своём словаре

#### Scenario: Ошибка с параметрами

- **WHEN** отклоняется загрузка файла из-за превышения предельного размера
- **THEN** тело ответа содержит код ошибки и параметр предельного размера
- **AND** отображаемое сообщение содержит подставленное значение предела

#### Scenario: Неизвестный клиенту код

- **WHEN** клиент получает код ошибки, отсутствующий в его словаре
- **THEN** отображается общее сообщение об ошибке
- **AND** код записывается в лог клиента

#### Scenario: Уникальность кодов

- **WHEN** выполняется проверка реестра кодов ошибок
- **THEN** все коды уникальны и каждому соответствует запись в словаре клиента

### Requirement: Пользовательские тексты вынесены в словарь

Компоненты интерфейса переведённых разделов MUST NOT содержать литеральных строк, предназначенных для показа пользователю. Все такие строки SHALL находиться в словаре и извлекаться по ключу.

#### Scenario: Литеральная строка в переведённом разделе

- **WHEN** в компоненте переведённого раздела появляется литеральная строка на кириллице, предназначенная для показа пользователю
- **THEN** проверка в непрерывной интеграции завершается неуспешно с указанием файла и строки

#### Scenario: Использование отсутствующего ключа

- **WHEN** код обращается к ключу, отсутствующему в словаре
- **THEN** проверка в непрерывной интеграции завершается неуспешно с указанием ключа

### Requirement: Определение языка пользователя

Язык интерфейса SHALL определяться в порядке: сохранённая настройка пользователя, затем заголовок предпочитаемых языков запроса, затем русский язык по умолчанию.

#### Scenario: Настройка пользователя задана

- **WHEN** у пользователя сохранена настройка языка
- **THEN** интерфейс использует этот язык независимо от заголовка предпочитаемых языков

#### Scenario: Настройка не задана

- **WHEN** настройка языка не задана
- **THEN** используется язык из заголовка предпочитаемых языков, если он поддерживается
- **AND** иначе используется русский язык

### Requirement: Форматирование величин с учётом локали

Даты, числа, единицы измерения и формы существительных при числительных SHALL формироваться общими функциями форматирования с учётом текущего языка. Склейка форматированных значений вручную MUST NOT использоваться.

#### Scenario: Согласование существительного с числительным

- **WHEN** отображается количество элементов, равное одному, двум и пяти
- **THEN** форма существительного соответствует правилам русского языка для каждого из этих числительных

#### Scenario: Формат даты

- **WHEN** отображается дата
- **THEN** она отформатирована средствами локали текущего языка

### Requirement: Добавление языка не требует изменений кода

Добавление поддержки нового языка SHALL сводиться к добавлению словаря и регистрации языка в перечне поддерживаемых.

#### Scenario: Добавление нового словаря

- **WHEN** добавлен полный словарь нового языка и язык зарегистрирован
- **THEN** интерфейс отображается на этом языке без изменений в компонентах

#### Scenario: Неполный словарь

- **WHEN** в словаре зарегистрированного языка отсутствуют ключи, присутствующие в основном словаре
- **THEN** проверка полноты словарей завершается неуспешно с перечнем недостающих ключей
