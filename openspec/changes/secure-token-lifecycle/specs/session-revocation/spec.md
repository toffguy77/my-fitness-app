## ADDED Requirements

### Requirement: Смена и сброс пароля завершают все сессии

При успешной смене пароля аутентифицированным пользователем и при успешном сбросе пароля по ссылке восстановления система SHALL отозвать все refresh-токены пользователя и сделать недействительными все ранее выданные access-токены этого пользователя.

#### Scenario: Сброс пароля отзывает refresh-токены

- **WHEN** пользователь успешно завершает сброс пароля
- **THEN** все записи в `refresh_tokens` для этого пользователя имеют непустое `revoked_at`
- **AND** попытка обновления токена по любому из прежних refresh-токенов возвращает `401`

#### Scenario: Сброс пароля делает недействительными access-токены

- **WHEN** пользователь успешно завершает сброс пароля
- **AND** злоумышленник обращается к защищённому эндпоинту с access-токеном, выданным до сброса
- **THEN** API отвечает статусом `401` не позднее чем через 30 секунд после сброса

#### Scenario: Смена пароля из настроек отзывает сессии

- **WHEN** пользователь успешно меняет пароль через настройки
- **THEN** все прежние refresh-токены пользователя отозваны
- **AND** текущая сессия пользователя, инициировавшего смену, получает новую пару токенов и остаётся рабочей

### Requirement: Версия токенов пользователя

Каждый пользователь SHALL иметь числовую версию токенов. Выпускаемые access-токены MUST содержать значение этой версии. Middleware аутентификации MUST отклонять токен, версия в котором не совпадает с текущей версией пользователя.

#### Scenario: Токен со старой версией

- **WHEN** версия токенов пользователя увеличена
- **AND** выполняется запрос с access-токеном, содержащим предыдущую версию
- **THEN** API отвечает статусом `401`

#### Scenario: Токен с актуальной версией

- **WHEN** выполняется запрос с access-токеном, версия в котором совпадает с текущей версией пользователя
- **THEN** запрос обрабатывается штатно

#### Scenario: Задержка распространения отзыва

- **WHEN** версия токенов пользователя увеличена
- **THEN** все инстансы API начинают отклонять токены прежней версии не позднее чем через 30 секунд

### Requirement: Отсутствие ложных сообщений об отзыве сессий

Система MUST NOT записывать в лог сообщение об отзыве сессий, если отзыв фактически не выполнен.

#### Scenario: Проверка реализации отзыва

- **WHEN** вызывается функция инвалидации сессий пользователя
- **THEN** в базе данных изменяется состояние refresh-токенов и версия токенов пользователя
- **AND** запись в лог делается только после успешного изменения
