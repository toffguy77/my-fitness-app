## ADDED Requirements

### Requirement: Строгая валидация конфигурации в production

Сервис SHALL отказываться стартовать, когда `NODE_ENV=production` и хотя бы одна обязательная переменная окружения отсутствует, пуста или содержит небезопасное значение. Список обязательных переменных: `JWT_SECRET`, `DATABASE_URL` или полный набор `DB_HOST`/`DB_NAME`/`DB_USER`/`DB_PASSWORD`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM_ADDRESS`.

#### Scenario: Отсутствует JWT_SECRET в production

- **WHEN** сервис запускается с `NODE_ENV=production` и незаданным `JWT_SECRET`
- **THEN** `config.Load()` возвращает ошибку, содержащую имя `JWT_SECRET`
- **AND** процесс завершается с ненулевым кодом возврата и не начинает слушать порт

#### Scenario: Все обязательные переменные заданы

- **WHEN** сервис запускается с `NODE_ENV=production` и всеми заданными обязательными переменными
- **THEN** `config.Load()` возвращает конфигурацию без ошибки
- **AND** сервис начинает слушать порт

### Requirement: Запрет небезопасного JWT-секрета

Сервис SHALL считать значение `JWT_SECRET` небезопасным, если оно короче 32 байт или совпадает с одним из известных плейсхолдеров (`dev-secret-key`, `change-me`, `secret`, `test`). В `production` небезопасный секрет MUST приводить к отказу старта; в остальных окружениях — к предупреждению в логе уровня `WARN`.

#### Scenario: Дефолтный секрет в production

- **WHEN** сервис запускается с `NODE_ENV=production` и `JWT_SECRET=dev-secret-key`
- **THEN** `config.Load()` возвращает ошибку о небезопасном значении `JWT_SECRET`
- **AND** процесс не стартует

#### Scenario: Короткий секрет в production

- **WHEN** сервис запускается с `NODE_ENV=production` и `JWT_SECRET` длиной 16 байт
- **THEN** `config.Load()` возвращает ошибку с указанием минимальной длины 32 байта

#### Scenario: Дефолтный секрет в development

- **WHEN** сервис запускается с `NODE_ENV=development` и незаданным `JWT_SECRET`
- **THEN** сервис стартует
- **AND** в лог пишется запись уровня `WARN` о использовании небезопасного дефолтного секрета

### Requirement: Агрегированный отчёт о проблемах конфигурации

`config.Load()` SHALL собирать все обнаруженные проблемы конфигурации и возвращать их одной агрегированной ошибкой, а не прерываться на первой.

#### Scenario: Несколько незаданных переменных

- **WHEN** сервис запускается с `NODE_ENV=production` без `JWT_SECRET` и без `SMTP_PASSWORD`
- **THEN** возвращаемая ошибка содержит упоминание и `JWT_SECRET`, и `SMTP_PASSWORD`
- **AND** при старте в лог выводится по одной строке на каждую проблему

### Requirement: Явное объявление опциональных возможностей

Конфигурация SHALL содержать набор флагов включённых опциональных возможностей, вычисляемых из наличия соответствующих ключей: распознавание еды (`OPENROUTER_API_KEY`), еженедельные фото, вложения чата, медиа контента, аватары профиля (соответствующие ключи S3). При старте сервис MUST записать в лог уровня `WARN` перечень выключенных возможностей.

#### Scenario: Отсутствует ключ OpenRouter

- **WHEN** сервис стартует без `OPENROUTER_API_KEY`
- **THEN** сервис стартует успешно
- **AND** в лог пишется `WARN` с указанием, что распознавание еды выключено
- **AND** флаг возможности «распознавание еды» имеет значение «выключено»

#### Scenario: Обращение к выключенной возможности

- **WHEN** аутентифицированный пользователь вызывает эндпоинт возможности, флаг которой выключен
- **THEN** API отвечает статусом `503`
- **AND** тело ответа содержит понятное пользователю сообщение на русском языке

### Requirement: Диагностика конфигурации через health-эндпоинт

`GET /health` SHALL возвращать поле `features` — объект, в котором ключ соответствует опциональной возможности, а значение — булев признак её включённости.

#### Scenario: Запрос состояния возможностей

- **WHEN** выполняется `GET /health` на инстансе без заданных S3-ключей и с заданным `OPENROUTER_API_KEY`
- **THEN** ответ содержит `features` с истинным значением для распознавания еды и ложным для загрузок в S3
