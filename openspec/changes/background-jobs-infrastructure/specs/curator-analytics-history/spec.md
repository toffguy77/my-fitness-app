## ADDED Requirements

### Requirement: Ежедневный снапшот метрик куратора

Система SHALL ежедневно сохранять снимок текущих метрик каждого активного куратора в таблицу дневных снапшотов. Повторный сбор за ту же дату MUST обновлять существующую запись, а не создавать дубликат.

#### Scenario: Сбор снапшота за день

- **WHEN** выполняется ежедневная задача сбора снапшотов
- **THEN** для каждого куратора с активными клиентами создаётся или обновляется запись за текущую дату
- **AND** запись содержит число клиентов, число клиентов, требующих внимания, средний процент КБЖУ, число непрочитанных сообщений, число активных, просроченных и выполненных задач и средний стрик клиентов

#### Scenario: Повторный сбор за ту же дату

- **WHEN** ежедневная задача выполняется повторно в те же сутки
- **THEN** запись за эту дату обновляется
- **AND** количество записей за дату остаётся равным одному на куратора

### Requirement: Еженедельный снапшот и бенчмарк платформы

Система SHALL еженедельно сохранять снимок недельных метрик каждого куратора и агрегированный бенчмарк по всей платформе за завершившуюся неделю.

#### Scenario: Сбор недельных данных

- **WHEN** выполняется еженедельная задача
- **THEN** для каждого куратора создаётся или обновляется запись недельного снапшота за начало завершившейся недели
- **AND** создаётся или обновляется запись бенчмарка платформы за ту же неделю с числом учтённых кураторов

### Requirement: Выдача истории и бенчмарка куратору

Эндпоинты истории и бенчмарка SHALL возвращать накопленные данные куратора. При отсутствии накопленных данных ответ MUST содержать пустой набор, а клиент MUST отображать состояние накопления данных, а не ошибку.

#### Scenario: История при наличии снапшотов

- **WHEN** куратор запрашивает `GET /api/v1/curator/analytics/history?period=daily&count=7` при наличии снапшотов
- **THEN** ответ содержит до семи записей, отсортированных по дате по убыванию

#### Scenario: История сразу после включения сбора

- **WHEN** куратор запрашивает историю до первого запуска задачи сбора
- **THEN** API отвечает статусом `200` с пустым набором
- **AND** интерфейс показывает сообщение о накоплении данных, а не ошибку

#### Scenario: Бенчмарк сравнивает куратора с платформой

- **WHEN** куратор запрашивает `GET /api/v1/curator/analytics/benchmark` при наличии недельных данных
- **THEN** ответ содержит недельные метрики куратора и соответствующие им средние значения по платформе за ту же неделю
