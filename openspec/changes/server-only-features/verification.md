# Проверка в браузере

Задача 4.2. Снято 2026-09-27 через `dev-proxy` на **3070**; API — локальный с
правками, база — dev. Учётная запись служебная, `e2e-client@burcev.test`.

## Избранное было сломано в четырёх местах, а не в одном

Предложение называло одну причину — «кнопки нет». Кнопки действительно не было,
но за ней нашлось ещё три, и каждая по отдельности делала функцию нерабочей:

| где | что было | как видно |
|---|---|---|
| Интерфейс | отметки нет | раздел избранного пуст всегда |
| `service.go` | `INSERT` в колонку `added_at`, которой нет — она `created_at` | `ERROR: column "added_at" does not exist` |
| `service.go` | числовой идентификатор из `products` отклонялся | в браузере `POST /favorites/10231 → 400` |
| `useFoodSearch.ts` | читалось поле `items`, сервер отдаёт `foods` | список пуст даже при заполненном избранном |

Последнее ломало и «Недавние»: тот же ответ, то же неверное поле. То есть список
недавних продуктов не показывался никогда, и заметить это было нечем — пропс со
значением по умолчанию `recentFoods = []` превращал `undefined` в пустой список,
а тесты хука подменяли ответ и сами говорили `items`.

Пятое: `loadFavoriteFoods` не звал никто, то есть избранное не загружалось даже
после того, как заполнилось бы.

## После

Над пустым полем поиска:

```
Недавние | Молоко пастеризованное 2,5%, «Рузское молоко», 1 кг, Россия, БЗМЖ
Избранное | Гречка | 100 г
```

В выдаче по запросу «молоко» — 19 отметок. Нажатие на отметку у строки из
таблицы `products`:

```
жму: Добавить Молоко пастеризованное 2,5%, «Рузское молоко» в избранное
POST /api/v1/food-tracker/favorites/82785 -> 200
GET  /api/v1/food-tracker/favorites -> 200
стало отмеченных: 1
```

`82785` — это идентификатор из `products`; сервер перевёл его в строку
`food_items` с постоянным идентификатором, и повторная отметка того же продукта
новой строки не создаёт (проверено тестом).

## Чего проверка не покрыла

- **Снятие отметки в браузере** — проверено запросом к API (`DELETE → 200`) и
  интеграционными тестами на настоящей базе, в браузере не нажималось.
- **Загрузка статьи файлом** — маршрут снят, а существующий импорт `.md` в
  редакторе этим изменением не трогался.
