## Why

Начинаем нативный iOS-клиент, за ним — нативный Android. Оба будут жить на общем `/api/v1` вместе с вебом: отдельную `/api/v2` под «замороженный» веб решили не заводить — вебу обратная совместимость не нужна (он выкатывается вместе с API из того же репозитория), а вторая версия удвоила бы бизнес-логику и вернула бы бэкпортирование, только в обратную сторону.

Совместимость нужна мобильным клиентам: выпущенная сборка живёт на телефоне месяцами и обновить её принудительно нельзя. Сейчас защищать её нечем:

1. **Контракт ответов нигде не записан.** `internal/router/testdata/routes.golden` фиксирует только пути (201 маршрут на `dev`), `scripts/check-api-contract.mjs` сверяет пути веба с ним же. Переименование поля, `null` вместо `[]` или новое значение перечисления проходят все проверки — и роняют декодер на телефоне.
2. **Типов для нативных клиентов нет.** Веб берёт типы из `@burcev/types`, Swift и Kotlin их не прочтут. Описывать каждое поле руками в двух языках — значит, что они разъедутся молча.
3. **Тест не может собрать настоящий роутер.** Обработчики и сервисы собираются прямо в `main()` (`apps/api/cmd/server/main.go:68-675`), `router.New` получает уже готовые `Deps`. Любая проверка живых ответов сегодня собирала бы свою копию зависимостей — и проверяла бы её, а не прод.

Это первый из пяти подпроектов iOS-клиента:

1. **Контракт** — это изменение.
2. API для мобилки — refresh-токен в теле и Keychain, APNs, `app-config` с `min_supported_version`, заголовок `X-Client`, universal links, OAuth с возвратом в приложение.
3. Каркас iOS — проект, сеть на сгенерированном клиенте, вход, интерфейс по роли, принудительное обновление, CI на macOS и TestFlight.
4. Клиентская часть — дашборд, дневник, вода, чат, push, удаление аккаунта.
5. Кабинет куратора.

Подпроекты 1 и 2 не зависят от Mac и идут параллельно; 3 опирается на оба; 4 и 5 — на 3. Момент отключения веб-кабинета выбирается позже, по измеримому условию; публичная часть веба (`/api/v1/public/*`) остаётся.

## What Changes

- Появляется OpenAPI 3.1-схема в `apps/api/openapi/`: корень, `paths/<модуль>.yaml`, `components/`. Описываются только операции, которые вызывает первая версия iOS (ядро клиента, кабинет куратора, удаление аккаунта — около 90–100 операций); каждая помечена `x-clients: [ios]`.
- Общая обёртка ответа `{status, data, message?, code?, params?}` и ошибка с машинным `code` описаны в схеме один раз.
- Сборка зависимостей API выносится из `main()` в `internal/app`, чтобы прод и тест контракта собирали один и тот же роутер.
- Тест контракта (`internal/contract/`, тег `integration`) прогоняет каждую операцию схемы на настоящем роутере и тестовой базе и проверяет запрос и ответ по схеме; в тесте объекты ответа считаются закрытыми. Операция или объявленный статус без сценария валит сборку. В CI тест без базы падает, а не пропускается.
- Тест в `internal/router/` требует, чтобы каждая операция схемы существовала в `routes.golden`.
- `make openapi` собирает схему в один файл на клиента — `apps/api/openapi/dist/ios.yaml`; файл коммитится, CI сверяет его со свежей сборкой.
- В `Static Checks` добавляется шаг `oasdiff breaking` против схемы целевой ветки. До отметки `x-first-release` в схеме — только отчёт, после — поломка валит сборку. Разрешённые поломки перечисляются в `apps/api/openapi/accepted-breaks.yaml`.
- Перечисления в ответах, которые будут расти, описываются как открытые строки; закрытые перечисления менять — поломка.

## Impact

**Бэкенд:**
- `apps/api/cmd/server/main.go:68-675` — сборка сервисов и обработчиков переезжает в `internal/app`; в `main()` остаются чтение конфигурации, миграции, запуск сервера и фоновых заданий. Поведение не меняется — сторожит `TestRoutesMatchGolden` (`internal/router/routes_test.go:47`).
- `apps/api/internal/router/router.go:47-86` — `Deps` и `New` не меняются, их заполняет `internal/app`.
- `apps/api/internal/shared/response/response.go:11-24` — форма `Response` закрепляется схемой; сам код не меняется.
- `apps/api/internal/shared/apperrors/` — коды ошибок (`codes.go`, 33 константы) становятся известными значениями открытого перечисления `ErrorCode` в схеме; тест сверяет список.
- `apps/api/internal/testsupport/schema.go:34` — `SchemaWithMigrations` пропускает тест без `TEST_DATABASE_URL`; тесту контракта нужен вариант, который при `CI=true` падает.
- Новые: `apps/api/openapi/**`, `apps/api/internal/app/`, `apps/api/internal/contract/`, тест сверки схемы с `routes.golden` в `apps/api/internal/router/`.
- `apps/api/Makefile` — цель `openapi` рядом с `sync-knowledge` (`Makefile:56`).
- `apps/api/go.mod` — `github.com/getkin/kin-openapi` (только в тестах).

**CI:**
- `.github/workflows/ci.yml:26-118` (`Static Checks`) — шаг «Check mobile API contract compatibility» (`scripts/check-mobile-contract.mjs` поверх `oasdiff breaking`); тот же скрипт пересобирает `dist/*.yaml` и падает, если закоммиченный файл отличается. Имена джоб не меняются — обязательные проверки ruleset'а не затронуты.
- `.github/workflows/ci.yml:228-270` (`Integration Tests`) — тест контракта идёт в существующем `make test-integration-ci`, отдельного шага не нужно.

**Фронтенд:** не меняется. `scripts/check-api-contract.mjs` работает как раньше.

**Зависимости:** `kin-openapi` (Go, тесты), `@redocly/cli` (сборка схемы, devDependency в корне), `oasdiff` (бинарь в CI).
