## Context

Каждый из перечисленных фрагментов появился естественно: `nutrition` был первой попыткой трекинга до появления `food-tracker`; корневой `next.config.ts` остался от структуры до перехода на workspaces; `useWebSocket` и `WebSocketProvider` писались под разные экраны; фича-флаги закладывались «на будущее». Проблема не в происхождении, а в том, что ничто в процессе не заставляет их убрать.

## Goals / Non-Goals

**Goals:**
- Убрать из прода эндпоинты, возвращающие выдуманные данные.
- Оставить один источник истины для конфигурации сборки и для WebSocket-клиента.
- Привести `CLAUDE.md` в соответствие с кодом.
- Сделать так, чтобы новая заглушка не могла тихо доехать до прода.

**Non-Goals:**
- Не занимаемся общим рефакторингом модуля `food-tracker`.
- Не удаляем миграции, создавшие таблицы для `nutrition`, если они используются `food-tracker`.
- Не вводим полноценную систему фича-флагов (это отдельная задача, если понадобится).

## Decisions

**Решение 1. Модуль `nutrition` удаляется, а не дописывается.**
Функциональность полностью покрыта `food-tracker` (`/food-tracker/entries` с CRUD, поиском, избранным, водой). Дописывать второй трекер не нужно.
*Проверка перед удалением:* убедиться, что фронтенд не обращается к `/api/v1/nutrition/*` и что таблицы, которые читает `food-tracker`, не создавались миграциями «для nutrition».
*Альтернатива:* оставить роуты, вернув `501 Not Implemented`. Отвергнута: мёртвый эндпоинт остаётся поверхностью атаки и строкой в документации API.

**Решение 2. React Compiler включается.**
`babel-plugin-react-compiler` уже в `devDependencies`, то есть комментарий «not installed» устарел. Проект на React 19 и Next.js 16, компилятор даёт выигрыш без изменения кода.
*Условие:* включаем, только если сборка и полный прогон Jest проходят. Если нет — выключаем и удаляем пакет вместе с флагом, чтобы не осталось третьего расхождения.
*Альтернатива:* оставить как есть. Отвергнута: расхождение между `CLAUDE.md`, корневым и рабочим конфигом уже вводило в заблуждение при ревизии.

**Решение 3. Из двух WebSocket-реализаций остаётся провайдер.**
`WebSocketProvider` даёт одно соединение на приложение; `useWebSocket` при использовании на нескольких экранах открывает несколько соединений к одному пользователю.
*Следствие:* потребители `useWebSocket` переключаются на контекст провайдера.
*Альтернатива:* оставить хук, провайдер удалить. Отвергнута: множественные соединения нагружают хаб и усложняют доставку событий.

**Решение 4. Проверка целостности в CI — три конкретных правила, а не общий линтер.**
1. Каждая переменная `NEXT_PUBLIC_*` из `apps/web/.env.local` встречается в исходниках `apps/web/src`.
2. В `apps/api/internal/modules/**/service.go` нет функций, которые содержат `TODO` и при этом возвращают литеральные данные вместо обращения к БД, — проверяется списком известных маркеров (`// TODO: Implement`) в файлах модулей, чьи роуты зарегистрированы.
3. В репозитории ровно один `next.config.*`.
*Почему списком правил, а не эвристикой:* правила должны быть понятны и не давать ложных срабатываний, иначе их отключат.

## Risks / Trade-offs

- **Риск: удаление `/nutrition/*` ломает неизвестного потребителя** (мобильный клиент, интеграция). → Задача 1.1 — проверка логов прода за 30 дней на обращения к этим путям; удаляем только при нулевом трафике.
- **Риск: включение React Compiler ломает компоненты с побочными эффектами в рендере.** → Полный прогон Jest и e2e, ручная проверка на dev перед прод-выкаткой; при проблемах — откат на выключенный флаг с удалением пакета.
- **Риск: переключение потребителей `useWebSocket` меняет поведение чата.** → Тесты чата и ручная проверка доставки сообщений и индикатора «печатает».
- **Trade-off: правило CI про `NEXT_PUBLIC_*`** может мешать заранее заводить переменные. Принимаем: заводить переменную вместе с кодом, который её читает.

## Migration Plan

1. Проверить трафик на `/api/v1/nutrition/*` в логах прода.
2. Удалить модуль и роуты, выкатить на dev.
3. Свести WebSocket-клиент, выкатить на dev, проверить чат вручную.
4. Решить вопрос React Compiler по результатам сборки и тестов.
5. Почистить конфигурации и `.env.local`, добавить проверку в CI.

**Откат:** все изменения — удаление кода без миграций БД; откат возвратом образа.
