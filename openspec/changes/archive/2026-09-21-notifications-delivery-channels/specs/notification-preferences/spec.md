## ADDED Requirements

### Requirement: Матрица предпочтений по типам событий и каналам

Пользователь SHALL управлять доставкой отдельно для каждой пары «тип события — канал». Уведомление в приложении MUST быть неотключаемым.

#### Scenario: Чтение предпочтений

- **WHEN** пользователь запрашивает свои предпочтения уведомлений
- **THEN** ответ содержит все поддерживаемые типы событий и для каждого — состояние каналов push и почты

#### Scenario: Отключение канала для типа события

- **WHEN** пользователь отключает push для назначенных задач
- **AND** для него создаётся уведомление о назначенной задаче
- **THEN** задание на доставку через push не создаётся
- **AND** уведомление в приложении создаётся

#### Scenario: Попытка отключить уведомления в приложении

- **WHEN** пользователь пытается отключить канал приложения для любого типа события
- **THEN** запрос отклоняется со статусом `400`

### Requirement: Значения предпочтений по умолчанию

Новый пользователь SHALL получать предпочтения по умолчанию, при которых срочные события доставляются через push, напоминания — почтой, а рассылка контента управляется по категориям.

#### Scenario: Предпочтения нового пользователя

- **WHEN** создаётся новый пользователь
- **THEN** для сообщений чата, назначенных задач, обновлённых планов и полученного фидбека push разрешён
- **AND** для напоминаний об отчёте разрешена почта

#### Scenario: Сохранение ранее сделанного выбора

- **WHEN** пользователь ранее отключил рассылку по категории контента
- **THEN** после перехода на новую модель предпочтений эта категория остаётся отключённой

### Requirement: Тихое время

Пользователь SHALL иметь возможность задать интервал суток, в который push не доставляется. Интервал MUST интерпретироваться в часовом поясе пользователя. Push, выпавший на этот интервал, MUST доставляться в начале ближайшего разрешённого времени, а не отменяться.

#### Scenario: Событие в тихое время

- **WHEN** уведомление создано во время, попадающее в тихий интервал пользователя
- **THEN** доставка через push откладывается до окончания интервала
- **AND** уведомление в приложении создаётся немедленно

#### Scenario: Смена часового пояса

- **WHEN** пользователь изменил часовой пояс
- **THEN** тихий интервал применяется в новом часовом поясе

### Requirement: Отписка от писем без входа в приложение

Каждое отправляемое сводное письмо SHALL содержать ссылку отписки, действующую без аутентификации. Переход по ссылке MUST отключать почтовый канал и MUST NOT предоставлять никакого другого доступа.

#### Scenario: Переход по ссылке отписки

- **WHEN** получатель переходит по ссылке отписки из письма
- **THEN** почтовый канал для соответствующего типа события отключается
- **AND** отображается подтверждение на русском языке

#### Scenario: Подделанная ссылка отписки

- **WHEN** выполняется переход по ссылке отписки с некорректной подписью
- **THEN** изменений в предпочтениях не происходит
- **AND** отображается сообщение об ошибке

### Requirement: Объяснение ограничений push на платформе

Интерфейс SHALL сообщать пользователю, если push недоступен на его платформе без дополнительных действий, и объяснять требуемое действие.

#### Scenario: Открытие в браузере на платформе с ограничением

- **WHEN** пользователь открывает настройки уведомлений в браузере, где push требует установки приложения на домашний экран
- **THEN** отображается объяснение и инструкция по установке
- **AND** переключатель push не отображается активным без выполнения условия
