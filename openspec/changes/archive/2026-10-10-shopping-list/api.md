# Контракт API `shopping-list`

## Отклонения

Записаны при реализации; всё ниже имеет приоритет над остальным текстом.

1. **Отдел «Хлеб и выпечка»**, как здесь, а не «Хлеб» из `design.md`.
2. **Категория продукта из общего каталога — номер.** Продукт, выбранный в
   поиске из `products`, переносится в `food_items` с `category =
   category_id::text` (`ensureFoodItemExists`). Сервер берёт название из
   `categories` по этому номеру, иначе — сам текст `food_items.category`.
   Сторож — интеграционный тест (категория «Птица» номером → «Мясо и птица»).
3. **Доля «Прочего»** проверяется на снимке таблицы `categories` с dev
   (`mealplan/testdata/catalogue_categories.tsv`, 338 названий, взвешено числом
   продуктов); категории, которые и называются «Прочее», не считаются. Сейчас
   27,1% < 30%. Категории openfoodfacts (`food_items`, в основном латиница и
   «Прочее») в снимок не входят: рецепты берут продукты из общего каталога.
4. **14 дней — включительно**: `to − from ≤ 13`. Без параметров `to` ищется в
   `from..from+6` (7 дней включительно). Окно ±30 дней планов к списку не
   применяется. Неверный формат, только один параметр, `to < from`, больше 14
   дней — `422 {code: "validation"}`, отдельных кодов нет.
5. **`has_plans`** — есть хотя бы одна строка `meal_plans` в диапазоне, даже без
   блюд; тогда `departments` и `at_home` пусты (экран говорит «нет продуктов»).
6. **Округление** решается по неокруглённой сумме: «свыше 500 г» — сумма
   > 500. Шум плавающей точки (340/1020 × 600) шага не стоит.
7. **Штуки**: подпись количества хотя бы одного вхождения оканчивается на «шт»
   или «шт.» (без учёта регистра) и `default_weight > 0`. `pieces` =
   ⌈сумма ÷ вес штуки⌉ по неокруглённой сумме, `piece_grams` = pieces × вес
   штуки, округлённое до грамма; `grams` — округлённая сумма, как у остальных.
8. **Названия** в отделе и в `at_home` упорядочены без учёта регистра, «ё» как
   «е»; `at_home` — по продукту, одинаковые названия схлопываются.
9. **На всякий случай отбрасываются** ингредиенты без веса и не «по вкусу» и
   версии с `total_grams = 0`: у одобренной версии их не бывает (отправка на
   проверку требует продукт и вес).
10. **Событие `shopping_list_opened`**: `days` обязателен, значения `"1"`…`"14"`;
    `shopping_list_shared`: `method` обязателен, `copy` | `share`. «Поделиться»,
    отменённое человеком (`AbortError`), ничего не отправляет; сломавшееся —
    копирует и шлёт `method: "copy"`.

Миграции нет. Обёртка ответов, коды ошибок, `snake_case` — как в
`recipe-catalogue/api.md`.

## Маршрут

`GET /api/v1/shopping-list?from=YYYY-MM-DD&to=YYYY-MM-DD` — `RequireRole("client")`,
только планы вызывающего; планы не создаются.

- Без `from`/`to`: `from` = сегодня (часовой пояс клиента, как у плана),
  `to` = последняя дата с планом в пределах `from..from+6`; если планов нет — `to = from`.
- `422`: неверный формат, `to < from`, диапазон длиннее 14 дней. Задан только один
  из параметров — `422`.

```ts
interface ShoppingItem {
  food_id: string
  name: string
  grams: number                 // округлено вверх: до 10 г, свыше 500 г — до 50 г
  pieces: number | null         // штуки, если продукт в рецептах указан «шт» и известен вес штуки
  piece_grams: number | null    // pieces × вес штуки (≈ для подписи «4 шт. (≈220 г)»)
  quantity_text: string         // готовая подпись: «130 г» или «4 шт. (≈220 г)»
}

interface ShoppingDepartment { name: string; items: ShoppingItem[] }   // порядок отделов фиксирован

interface ShoppingList {
  from: string
  to: string
  has_plans: boolean
  departments: ShoppingDepartment[]     // только непустые, «Прочее» последним
  at_home: string[]                     // «по вкусу», названия по алфавиту, без дублей
}
```

Отделы (порядок): «Овощи и зелень», «Фрукты и ягоды», «Мясо и птица», «Рыба и
морепродукты», «Молочное и яйца», «Крупы, макароны, бобовые», «Хлеб и выпечка»,
«Масла, соусы, специи», «Орехи и сухофрукты», «Замороженное», «Напитки», «Прочее».

## События аналитики (браузер)

`shopping_list_opened` (свойство `days`: число дней в диапазоне),
`shopping_list_shared` (свойство `method`: `copy` | `share`) — объявить в
`analytics/dictionary.go`.
