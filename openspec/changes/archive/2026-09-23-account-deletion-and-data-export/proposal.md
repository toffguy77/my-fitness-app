## Why

Кнопка «Удалить аккаунт» в настройках (`apps/web/src/features/settings/components/SettingsLocality.tsx:114-118`) показывает `window.confirm('Вы уверены?')` и затем `toast('Функция в разработке')`. Удаления нет ни на фронтенде, ни в API. Экспорта данных нет вовсе.

Приложение собирает вес, замеры тела, фотографии прогресса, дневник питания и переписку с куратором — это данные о здоровье. Российский 152-ФЗ требует прекращения обработки и уничтожения персональных данных по требованию субъекта, а страница `/legal/privacy` в приложении уже существует и, по всей видимости, такое право декларирует. Разрыв между декларацией и реализацией — не бэклог, а юридический риск.

Отдельно: у платформы есть роль куратора, который ведёт клиента. Удаление клиента затрагивает данные куратора (переписка, отчёты, планы) — просто `DELETE FROM users` недопустимо.

## What Changes

- Добавляется удаление аккаунта в два шага: запрос на удаление с подтверждением пароля, затем период ожидания 30 дней, в течение которого вход отменяет удаление.
- Добавляется немедленная деактивация: сразу после запроса пользователь выходит из системы, все сессии завершаются, профиль перестаёт быть видимым куратору, уведомления и письма прекращаются.
- По истечении периода ожидания фоновая задача выполняет необратимое удаление: персональные данные стираются, файлы в S3 удаляются, связанные записи анонимизируются или удаляются по явно заданной для каждой таблицы стратегии.
- Добавляется экспорт данных: `POST /api/v1/users/me/export` формирует архив, `GET /api/v1/users/me/export/:id` отдаёт его по одноразовой ссылке со сроком жизни 24 часа.
- Добавляется страница `/settings/privacy` с обеими операциями и явным описанием последствий.
- Страница `/legal/privacy` приводится в соответствие с фактическим поведением: сроки хранения, что удаляется, что сохраняется и почему.
- **BREAKING (данные):** для сообщений чата вводится анонимизация вместо удаления — переписка остаётся у куратора без персональных данных удалённого пользователя.

## Capabilities

### New Capabilities

- `account-lifecycle`: запрос на удаление, период отмены, деактивация, необратимое удаление и стратегия обработки связанных данных.
- `data-export`: состав, формат, порядок формирования и выдачи выгрузки персональных данных.

## Impact

**Бэкенд:**
- Новый модуль `apps/api/internal/modules/account/` — `handler.go`, `service.go`, `export.go`, `erasure.go`.
- Новая миграция `047_account_deletion`: колонки `users.deletion_requested_at`, `users.deleted_at`, `users.anonymized_at`; таблица `data_exports`.
- `apps/api/internal/shared/middleware/auth.go` — отказ в доступе деактивированному аккаунту.
- `apps/api/internal/modules/auth/service.go` — вход отменяет запланированное удаление.
- `apps/api/internal/modules/curator/service.go` — исключение деактивированных клиентов из выдач.
- `apps/api/internal/shared/storage/s3.go` — удаление объектов по префиксу пользователя.
- Задачи в реестре из `background-jobs-infrastructure`: `account.execute-deletions`, `cleanup.data-exports`.

**Фронтенд:**
- `apps/web/src/app/settings/privacy/page.tsx` — новая страница.
- `apps/web/src/features/settings/components/SettingsLocality.tsx:114-118` — заглушка заменяется переходом на новую страницу.
- `apps/web/src/app/legal/privacy/page.tsx` — актуализация текста.

**Зависимости:** архив формируется стандартными `archive/zip` и `encoding/json`.

**Порядок:** после `background-jobs-infrastructure` (нужен реестр задач) и `secure-token-lifecycle` (нужен отзыв сессий).
