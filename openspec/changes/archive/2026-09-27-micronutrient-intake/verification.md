# Проверка

Задачи 5.3 и 5.4. Снято 2026-09-27 через `dev-proxy` на 3070; API локальный с
правками, база dev, учётная запись служебная.

## Число сверено руками

Съедено 250 г продукта, у которого в справочнике `"iron": 0.00239` и
`"calcium": 0.053` (граммы на 100 г), и 100 г продукта из таблицы `products`, у
которого содержания микронутриентов нет.

| нутриент | ожидалось | показано |
|---|---|---|
| Железо | 0,00239 × 250/100 × 1000 = **5,975 мг** | 6 мг |
| Кальций | 0,053 × 2,5 × 1000 = **132,5 мг** | 132,5 мг |
| Витамин A | — | 132,8 мкг |
| Натрий | — | 375 мг |
| Витамин C | — | 5,3 мг |

Покрытие у всех: «по 1 из 2» — второй продукт содержания не знает.

## Что видно в браузере

```
Железо      → 6 / 18 мг      по 1 из 2
Витамин A   → 132.8 / 800 мкг по 1 из 2
Кальций     → 132.5 / 1000 мг по 1 из 2
Селен       → 55 мкг
Пищевые волокна → 20 г
```

Селен и пищевые волокна — норма без прогресса: содержания в съеденных продуктах
нет. Подробности по железу:

```
Железо
6 из 18 мг
Посчитано по 1 из 2 записей за день — это не меньше, чем получилось на самом деле.
```

## Что нашлось при проверке

**Ложный ноль у клетчатки.** Первый прогон показал «0 г из 20, по 2 из 2
записей» — то есть уверенное «вы не добрали» при том, что человек съел гречку.
Причина: у колонки `fiber_per_100` ноль неотличим от «не заполнено», и у гречки
из таблицы `products` он именно такой при десяти граммах клетчатки на 100 г.
Теперь ноль в колонке считается неизвестным; в jsonb — измеренным, потому что
ключ там появляется только когда импортёру было что записать.

Цена названа в коде: у продукта, где клетчатки действительно нет — креветки,
масло, — знание тоже теряется. Ошибаться в эту сторону правильнее.

**Потерянное потребление без нормы.** Второй прогон (профиль без пола) показал у
железа «норма зависит от пола и возраста» — и потерял посчитанные 6 мг. Теперь
съеденное показывается и без нормы: терять измеренное из-за незаполненного
профиля — та же ошибка, только наоборот.

## Чего проверка не покрыла

- **Прод.** Там 33 нутриента и те же данные справочника продуктов, но вход под
  служебной учётной записью недоступен: пароль другой, а живые аккаунты не
  используются. Проверка после выкатки — по данным и по `/ready`.
- **Полное покрытие.** Дня, у которого содержание известно у всех записей, в
  проверке не было: в справочнике таких продуктов меньшинство. Случай закрыт
  тестом.
