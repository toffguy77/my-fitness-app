## ADDED Requirements

### Requirement: Уведомление несёт адрес экрана

Каждое создаваемое уведомление SHALL иметь поле `target {kind, ids}` с `kind` из перечня `chat`, `task`, `weekly_feedback`, `plan`, `client`, `support_conversation`, `lead`, `article`, `export`, `notifications`. Все значения `ids` — строки (uuid или десятичный id пользователя). `GET /api/v1/notifications` MUST отдавать `target` у каждой записи; записи, созданные до изменения, отдают `{kind: "notifications"}` без `ids`. Адрес, которому не хватает нужного id, MUST заменяться на `{kind: "notifications"}`.

#### Scenario: Отзыв на недельный отчёт

- **WHEN** куратор отправляет отзыв на отчёт клиента
- **THEN** у созданного уведомления `feedback_received` поле `target` равно `{kind: "weekly_feedback", ids: {report_id: <id отчёта>}}`

#### Scenario: Назначенная задача

- **WHEN** куратор создаёт задачу клиенту
- **THEN** у уведомления `task_assigned` поле `target.kind` равно `task`, а `target.ids.task_id` — id задачи
- **AND** `target.ids.task_type` — тип задачи

#### Scenario: Старая запись

- **WHEN** запрашивается уведомление, созданное до миграции
- **THEN** его `target` равен `{kind: "notifications"}`

### Requirement: Каждый тип уведомления сопоставлен виду адреса

Тест SHALL проверять, что для каждого значения `NotificationType` объявлен вид `target`, и падать на типе без сопоставления.

#### Scenario: Добавлен новый тип без адреса

- **WHEN** в `types.go` добавлен тип уведомления без записи в таблице адресов
- **THEN** `go test ./internal/modules/notifications/` завершается ошибкой с именем типа

### Requirement: Пуш передаёт адрес и не передаёт лишнего

Полезная нагрузка APNs SHALL содержать `aps.alert.title`, `aps.alert.body`, `aps.thread-id`, `aps.category` (если у типа есть действия), `aps.badge`, а также `target` и — для уведомлений, а не сообщений чата, — `notification_id`. Она MUST NOT содержать адрес почты, вес, калории и иные значения дневника, кроме текста самого уведомления.

#### Scenario: Пуш о задаче

- **WHEN** отправляется пуш `task_assigned` о задаче не-тренировке
- **THEN** нагрузка содержит `aps.category = "TASK"` и `target.ids.task_id`

#### Scenario: Пуш о тренировке

- **WHEN** отправляется пуш о задаче с `task_type = workout`
- **THEN** нагрузка содержит `aps.category = "TASK_WORKOUT"` — без фонового действия «Выполнено», которому нужны тип и длительность (на устройстве «Выполнено» открывает приложение на листе выбора)

### Requirement: Значок считает важное непрочитанное

`aps.badge` SHALL равняться сумме непрочитанных уведомлений категории `main` и непрочитанных сообщений чата пользователя на момент отправки. Непрочитанное категории `content` MUST NOT входить в значок.

#### Scenario: Две статьи и одно сообщение

- **WHEN** у пользователя 2 непрочитанных уведомления `content`, 0 `main` и 1 непрочитанное сообщение
- **THEN** `aps.badge` равен 1

### Requirement: Тихое обновление счётчиков

При изменении числа непрочитанного (новое уведомление `main`, прочтение, новое сообщение чата) сервер SHALL отправлять на устройства iOS пользователя фоновый пуш `content-available: 1` без `alert` и с новым `badge` не чаще раза в минуту на устройство.

#### Scenario: Прочитано в вебе

- **WHEN** пользователь прочитал все уведомления в браузере
- **THEN** на его iPhone отправлен фоновый пуш с `badge: 0` и без текста
