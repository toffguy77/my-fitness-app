## ADDED Requirements

### Requirement: Отсутствие имитации проверок

Шаг непрерывной интеграции, выводящий сообщение об успешном прохождении проверки, SHALL фактически выполнять эту проверку. Шаги, лишь печатающие сообщение об успехе, MUST быть удалены.

#### Scenario: Проверка порога покрытия

- **WHEN** покрытие тестами опускается ниже установленного порога
- **THEN** соответствующая джоба завершается неуспешно

#### Scenario: Отсутствие декоративных шагов

- **WHEN** выполняется проверка конфигурации CI на наличие шагов, печатающих сообщение об успехе проверки без её выполнения
- **THEN** таких шагов не обнаружено

### Requirement: Порог покрытия для обеих частей приложения

Непрерывная интеграция SHALL проверять покрытие тестами и фронтенда, и бэкенда, и завершаться неуспешно при снижении покрытия ниже установленного порога.

#### Scenario: Снижение покрытия бэкенда

- **WHEN** покрытие кода бэкенда опускается ниже установленного порога
- **THEN** джоба тестов бэкенда завершается неуспешно с указанием фактического и требуемого значений

### Requirement: Сквозные тесты выполняются на каждом изменении

Непрерывная интеграция SHALL выполнять набор сквозных тестов на поднятом приложении с реальной базой данных при каждом запросе на слияние. Результат MUST блокировать слияние.

#### Scenario: Фронтенд обращается к несуществующему маршруту API

- **WHEN** фронтенд вызывает путь API, который не зарегистрирован в роутере
- **AND** этот сценарий покрыт сквозным тестом
- **THEN** сквозной тест завершается неуспешно
- **AND** слияние заблокировано

#### Scenario: Сохранение отчёта

- **WHEN** джоба сквозных тестов завершилась
- **THEN** отчёт и артефакты неуспешных сценариев сохранены и доступны для скачивания

### Requirement: Обнаружение состояний гонки

Тесты бэкенда SHALL выполняться с включённым детектором гонок.

#### Scenario: Гонка при конкурентном доступе

- **WHEN** тест выполняет конкурентный доступ к разделяемой структуре без синхронизации
- **THEN** прогон тестов завершается неуспешно с отчётом детектора гонок

### Requirement: Статический анализ бэкенда

Непрерывная интеграция SHALL выполнять статический анализ кода на Go набором анализаторов, включающим проверку необработанных ошибок, незакрытых тел ответов, незакрытых результатов запросов к базе данных и отсутствия передачи контекста. Обнаруженные проблемы MUST блокировать слияние.

#### Scenario: Незакрытый результат запроса

- **WHEN** в коде появляется запрос к базе данных, результат которого не закрывается
- **THEN** джоба статического анализа завершается неуспешно

### Requirement: Проверки безопасности блокируют слияние

Проверки уязвимостей зависимостей, правил безопасности линтера, сканирования образов и поиска секретов SHALL блокировать слияние. Исключение отдельной находки MUST оформляться явной записью с причиной.

#### Scenario: Уязвимость высокого уровня в зависимости

- **WHEN** в зависимостях обнаружена уязвимость высокого уровня без оформленного исключения
- **THEN** джоба проверок безопасности завершается неуспешно

#### Scenario: Оформленное исключение

- **WHEN** находка внесена в файл исключений с указанием причины
- **THEN** джоба проверок безопасности завершается успешно

### Requirement: Проверка миграций базы данных

Непрерывная интеграция SHALL применять все миграции к чистой базе данных вперёд и затем откатывать их назад.

#### Scenario: Некорректная миграция отката

- **WHEN** миграция отката не может быть применена
- **THEN** джоба проверки миграций завершается неуспешно с указанием номера миграции

### Requirement: Однократная сборка образов

Образы контейнеров SHALL собираться в рамках одного запуска непрерывной интеграции не более одного раза для каждого сервиса и переиспользоваться остальными джобами.

#### Scenario: Проверка количества сборок

- **WHEN** завершается запуск непрерывной интеграции
- **THEN** количество операций сборки образа для каждого сервиса равно одному

### Requirement: Развёртывание связано с успешной интеграцией

Развёртывание SHALL запускаться только после успешного прохождения обязательных проверок. После развёртывания система MUST дождаться успешного ответа пробы готовности и пометить развёртывание неуспешным при её недостижении в отведённое время.

#### Scenario: Развёртывание среды разработки

- **WHEN** обязательные проверки на ветке разработки завершились успешно
- **THEN** запускается развёртывание среды разработки
- **AND** после развёртывания выполняется опрос пробы готовности до успешного ответа

#### Scenario: Проба готовности не отвечает после развёртывания

- **WHEN** после развёртывания проба готовности не возвращает успешный ответ в отведённое время
- **THEN** развёртывание помечается неуспешным
- **AND** формируется оповещение

#### Scenario: Развёртывание в производственную среду

- **WHEN** на основной ветке создан тег версии
- **AND** обязательные проверки завершились успешно
- **THEN** запускается развёртывание производственной среды

### Requirement: Обязательный набор проверок для слияния

Слияние в защищённые ветки SHALL быть возможно только при успешном завершении проверок: тесты фронтенда, тесты бэкенда с детектором гонок, статический анализ, интеграционные тесты, сквозные тесты, сборка, целостность кодовой базы, проверки безопасности.

#### Scenario: Неуспешная обязательная проверка

- **WHEN** любая из обязательных проверок завершилась неуспешно
- **THEN** слияние запроса на изменение заблокировано
