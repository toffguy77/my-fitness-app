## ADDED Requirements

### Requirement: Экран ошибки вместо дефолтного экрана фреймворка

При необработанной ошибке рендера приложение SHALL показывать собственный экран на русском языке, содержащий понятное объяснение, действие повтора, ссылку на главную и идентификатор ошибки. Дефолтный экран ошибки фреймворка MUST NOT отображаться пользователю в production.

#### Scenario: Ошибка рендера в сегменте приложения

- **WHEN** компонент внутри сегмента приложения выбрасывает ошибку при рендере
- **THEN** отображается собственный экран ошибки на русском языке
- **AND** экран содержит кнопку повтора и ссылку на главную
- **AND** экран содержит идентификатор ошибки

#### Scenario: Ошибка в корневом layout

- **WHEN** ошибка происходит в корневом layout
- **THEN** отображается экран `global-error` на русском языке с возможностью перезагрузки

#### Scenario: Повтор после ошибки

- **WHEN** пользователь нажимает кнопку повтора на экране ошибки
- **THEN** сегмент перерисовывается заново
- **AND** при успешном рендере отображается обычное содержимое

### Requirement: Страница несуществующего маршрута

Обращение к несуществующему маршруту SHALL приводить к собственной странице на русском языке с навигацией к основным разделам.

#### Scenario: Несуществующий URL

- **WHEN** пользователь открывает адрес, которому не соответствует ни один маршрут
- **THEN** отображается собственная страница «страница не найдена» на русском языке
- **AND** ответ имеет статус `404`

### Requirement: Изоляция сбоя виджета от страницы

Падение отдельного виджета SHALL NOT приводить к падению всей страницы. Виджет, обёрнутый границей ошибок, MUST заменяться локальным состоянием ошибки с возможностью повтора, а остальная страница MUST оставаться работоспособной.

#### Scenario: Падение виджета на дашборде

- **WHEN** виджет графика на дашборде выбрасывает ошибку при рендере
- **THEN** на его месте отображается локальное состояние ошибки с кнопкой повтора
- **AND** остальные виджеты дашборда отображаются и работают

### Requirement: Отправка необработанных ошибок клиента

Приложение SHALL перехватывать необработанные ошибки и отклонённые промисы и отправлять их на сервер. Отправляемая запись MUST содержать идентификатор ошибки, сообщение, стек, путь страницы и версию приложения.

#### Scenario: Необработанная ошибка

- **WHEN** на странице возникает необработанная ошибка JavaScript
- **THEN** на сервер отправляется запись с идентификатором ошибки, сообщением, стеком, путём и версией приложения

#### Scenario: Отклонённый промис

- **WHEN** промис отклоняется без обработчика
- **THEN** на сервер отправляется запись того же формата

#### Scenario: Совпадение идентификатора

- **WHEN** пользователю показан экран ошибки с идентификатором
- **THEN** отправленная на сервер запись содержит тот же идентификатор

#### Scenario: Ограничение потока ошибок

- **WHEN** одна и та же ошибка возникает многократно за короткий промежуток
- **THEN** на сервер отправляется ограниченное число записей, а не каждое возникновение

### Requirement: Различение потери соединения и ошибки сервера

Интерфейс SHALL отличать недоступность сети от ошибочного ответа сервера и показывать для них разные сообщения.

#### Scenario: Отсутствие сети

- **WHEN** запрос к API не выполняется из-за отсутствия соединения
- **THEN** пользователю показывается сообщение о проблеме с соединением и предложение повторить
- **AND** сообщение об ошибке сервера не показывается

#### Scenario: Ошибка сервера

- **WHEN** API отвечает статусом `500`
- **THEN** пользователю показывается сообщение о временной ошибке сервиса с идентификатором ошибки
