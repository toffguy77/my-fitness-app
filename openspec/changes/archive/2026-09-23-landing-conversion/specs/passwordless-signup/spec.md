## ADDED Requirements

### Requirement: Запрос ссылки входа по адресу почты

Система SHALL по запросу с адресом почты отправлять на него одноразовую ссылку входа. Ответ на запрос MUST быть одинаков независимо от того, существует ли аккаунт с таким адресом.

#### Scenario: Аккаунт существует

- **WHEN** посетитель запрашивает ссылку для адреса, на который зарегистрирован аккаунт
- **THEN** на адрес отправляется письмо со ссылкой входа
- **AND** ответ не сообщает о существовании аккаунта

#### Scenario: Аккаунта не существует

- **WHEN** посетитель запрашивает ссылку для адреса, на который аккаунта нет
- **THEN** на адрес отправляется письмо со ссылкой, создающей аккаунт
- **AND** ответ совпадает с ответом для существующего аккаунта

#### Scenario: Превышение частоты запросов

- **WHEN** запросы ссылки с одного адреса или на один почтовый ящик превышают установленный предел
- **THEN** запрос отклоняется
- **AND** письмо не отправляется

#### Scenario: Отправка почты недоступна

- **WHEN** способность отправки почты выключена в развёртывании
- **THEN** запрос ссылки отвечает отказом о недоступности способности
- **AND** вход по паролю остаётся доступен

### Requirement: Погашение ссылки входа

Ссылка входа SHALL действовать не дольше пятнадцати минут и MUST гаситься при первом использовании. Повторное использование MUST NOT выдавать сессию.

#### Scenario: Переход по действующей ссылке

- **WHEN** посетитель переходит по ссылке в течение срока её действия
- **THEN** выдаётся сессия
- **AND** ссылка становится недействительной

#### Scenario: Повторный переход

- **WHEN** посетитель переходит по уже использованной ссылке
- **THEN** сессия не выдаётся
- **AND** предлагается запросить новую ссылку

#### Scenario: Истёкшая ссылка

- **WHEN** посетитель переходит по ссылке позже пятнадцати минут с момента выдачи
- **THEN** сессия не выдаётся
- **AND** предлагается запросить новую ссылку

#### Scenario: Подделанная ссылка

- **WHEN** предъявлен токен, не выданный системой
- **THEN** сессия не выдаётся
- **AND** ответ не отличается от ответа на истёкшую ссылку

### Requirement: Создание аккаунта по ссылке входа

Переход по ссылке, выданной на адрес без аккаунта, SHALL создавать аккаунт с этим адресом. Адрес такого аккаунта MUST считаться подтверждённым.

#### Scenario: Первый вход создаёт аккаунт

- **WHEN** посетитель переходит по ссылке, выданной на адрес без аккаунта
- **THEN** создаётся аккаунт с этим адресом
- **AND** адрес помечен подтверждённым
- **AND** отдельное письмо подтверждения адреса не отправляется

#### Scenario: Перенос сохранённой заявки

- **WHEN** посетитель переходит по ссылке
- **AND** в его браузере сохранён токен заявки
- **THEN** параметры и результат расчёта из заявки переносятся в профиль
- **AND** повторный ввод параметров не запрашивается

### Requirement: Согласия при создании аккаунта по ссылке

Аккаунт, создаваемый по ссылке входа, SHALL получать записи о согласиях наравне с аккаунтом, созданным обычной регистрацией. Согласия MUST запрашиваться до отправки письма.

#### Scenario: Согласия записаны при создании аккаунта

- **WHEN** по ссылке создаётся новый аккаунт
- **THEN** сохраняются согласия на условия использования, политику конфиденциальности и обработку персональных данных
- **AND** для каждого сохраняются время, адрес и клиент

#### Scenario: Обязательные согласия не даны

- **WHEN** посетитель запрашивает ссылку, не дав обязательные согласия
- **THEN** ссылка не выдаётся
- **AND** письмо не отправляется

#### Scenario: Вход в существующий аккаунт не требует согласий заново

- **WHEN** по ссылке выполняется вход в существующий аккаунт
- **THEN** новые записи о согласиях не создаются
- **AND** существующие записи не изменяются

#### Scenario: Согласия из заявки не дублируются

- **WHEN** создаётся аккаунт по ссылке
- **AND** переносится заявка с ранее данными согласиями на обработку данных и на связь
- **THEN** согласия заявки переходят на аккаунт
- **AND** повторные записи тех же согласий не создаются

### Requirement: Аккаунт без пароля

Аккаунт, созданный по ссылке входа, SHALL существовать без пароля. Попытка входа по паролю в такой аккаунт MUST NOT раскрывать отсутствие пароля.

#### Scenario: Вход по паролю в беспарольный аккаунт

- **WHEN** выполняется попытка входа по паролю в аккаунт без пароля
- **THEN** ответ совпадает с ответом на неверный пароль
- **AND** ответ не отличается от него и по времени

#### Scenario: Пустое сохранённое значение пароля не является паролем

- **WHEN** у аккаунта сохранено пустое значение пароля
- **AND** выполняется попытка входа с любым паролем, включая пустой
- **THEN** вход не выполняется
- **AND** ответ совпадает с ответом на неверный пароль

#### Scenario: Миграция сохранённого пароля не затронута

- **WHEN** у аккаунта сохранён непустой пароль в устаревшем виде
- **AND** предъявлен совпадающий с ним пароль
- **THEN** вход выполняется
- **AND** сохранённое значение приводится к текущему виду

#### Scenario: Установка пароля позже

- **WHEN** владелец аккаунта без пароля задаёт пароль в настройках
- **THEN** вход по паролю становится доступен
- **AND** вход по ссылке остаётся доступен

#### Scenario: Существующие аккаунты не затронуты

- **WHEN** владелец аккаунта с паролем входит по паролю
- **THEN** вход выполняется как прежде
