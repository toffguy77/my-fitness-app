## Why

Уведомления существуют только внутри приложения. `apps/api/internal/modules/notifications/service.go:266-320` — `CreateNotification` пишет строку в таблицу `notifications` и на этом всё: ни писем, ни push. Поиск по модулю не находит ни SMTP, ни web push, ни каких-либо внешних каналов.

Продукт при этом устроен вокруг диалога куратора и клиента. Куратор ставит задачу, публикует недельный план, отвечает на отчёт, пишет в чат — и клиент узнаёт об этом, только если сам откроет приложение. Это подрывает и ретеншн, и ценность работы куратора: он пишет в пустоту и не знает, дошло ли.

PWA уже настроен (`next-pwa` в `apps/web/next.config.ts`), service worker регистрируется, то есть техническая основа для web push есть и не используется.

Отдельно: механизм предпочтений покрывает только рассылку контента — `content_notification_preferences` (`apps/api/internal/modules/notifications/preferences.go`), и учитывается он ровно в одном месте (`content/service.go:1250`). Уведомления о задачах, планах, фидбеке и сообщениях создаются безусловно, а страница `/settings/notifications` создаёт у пользователя впечатление более широкого управления, чем есть.

## What Changes

- Вводится слой доставки: одно доменное событие порождает уведомление в приложении и, по предпочтениям пользователя, доставку через web push и электронную почту.
- Добавляется web push: подписка через существующий service worker, хранение подписок, отправка через протокол Web Push с ключами VAPID.
- Добавляется доставка письмами по существующей SMTP-инфраструктуре (`internal/shared/email`) — для событий, которые пользователь не увидел в приложении в течение заданного времени.
- Вводится сводное письмо-дайджест вместо потока писем: события копятся и уходят одним письмом не чаще заданной частоты.
- Предпочтения расширяются со «только контент» до матрицы «тип события × канал», с разумными значениями по умолчанию.
- Добавляется «тихое время» — интервал, в который push не доставляется, с учётом часового пояса пользователя (поле часового пояса уже есть, `internal/shared/middleware/timezone.go`).
- Добавляется отписка от писем одним нажатием по подписанной ссылке без входа в приложение.
- Добавляется учёт доставки: по каждому уведомлению видно, в какие каналы оно ушло и с каким результатом.
- Страница `/settings/notifications` переписывается под новую матрицу предпочтений.

## Capabilities

### New Capabilities

- `notification-delivery`: как доменное событие превращается в доставку по каналам, порядок и условия отправки, обработка отказов, учёт результата.
- `notification-preferences`: матрица предпочтений по типам событий и каналам, значения по умолчанию, тихое время, отписка от писем.

## Impact

**Бэкенд:**
- `apps/api/internal/modules/notifications/service.go:266-320` — `CreateNotification` начинает порождать доставку.
- Новые `internal/modules/notifications/delivery.go`, `push.go`, `digest.go`.
- `internal/modules/notifications/preferences.go` — расширение модели предпочтений.
- `internal/shared/email/` — шаблоны письма о событии и дайджеста.
- Новые эндпоинты: подписка и отписка на push, чтение и запись матрицы предпочтений, отписка от писем по подписанной ссылке.
- Задачи в реестре из `background-jobs-infrastructure`: отправка отложенных писем, сборка дайджестов, чистка недействительных push-подписок.
- Новая миграция `048_notification_delivery`: `push_subscriptions`, `notification_deliveries`, расширение таблицы предпочтений, `users.quiet_hours_*`.
- Конфигурация: ключи VAPID — обязательные при включённом push, опциональная возможность в терминах изменения `harden-config-and-secrets`.

**Фронтенд:**
- `apps/web/src/features/notifications/` — запрос разрешения на push, подписка, управление матрицей предпочтений.
- `apps/web/src/app/settings/notifications/page.tsx` — переработка.
- Service worker — обработчик события push и перехода по уведомлению.
- Новая страница отписки от писем, доступная без входа.

**Зависимости:** библиотека Web Push для Go (протокол RFC 8291/8292).

**Порядок:** после `background-jobs-infrastructure` (нужны задачи) и `harden-config-and-secrets` (ключи VAPID как опциональная возможность). Желательно после `secure-token-lifecycle` — подписка на push требует аутентифицированного запроса.
