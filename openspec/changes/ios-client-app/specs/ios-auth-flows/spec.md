## ADDED Requirements

### Requirement: Экран входа предлагает все включённые способы

Экран входа SHALL показывать «Вход с Apple» (системная кнопка `SignInWithAppleButton`) первым, затем кнопки провайдеров из `GET /auth/providers`, поле почты с «Получить ссылку для входа» и «Войти с паролем». Выключенный провайдер MUST NOT показываться; «Вход с Apple» показывается, когда `apple` есть в списке. Ссылка на почту запрашивается после согласий (сервер принимает запрос только с ними).

#### Scenario: VK выключен на сервере

- **WHEN** `GET /auth/providers` возвращает только `yandex` и `apple`
- **THEN** на экране входа есть «Вход с Apple» и «Яндекс ID» и нет «VK ID»

### Requirement: Новый аккаунт сначала принимает согласия

После первого входа через Apple, Яндекс или VK, создающего аккаунт, приложение SHALL показывать экран согласий (оферта, политика, обработка персональных данных включая данные о здоровье — обязательные; маркетинг — необязательный) до любого другого экрана; без обязательных согласий кнопка «Продолжить» MUST быть недоступна.

#### Scenario: Попытка продолжить без согласия на ПДн

- **WHEN** новый пользователь отметил оферту и политику, но не согласие на обработку ПДн
- **THEN** «Продолжить» недоступна

### Requirement: Ссылка из письма входит в приложение

Открытие universal link `/auth/link/consume?token=` SHALL вызывать `POST /auth/native/magic-link/consume` и при успехе открывать следующий экран по правилу после входа; просроченная, использованная или поддельная ссылка (сервер отвечает на все три одинаково — `400 token_invalid`) MUST показывать «Ссылка устарела» с кнопкой «Получить новую».

#### Scenario: Просроченная ссылка

- **WHEN** открыта ссылка старше 15 минут
- **THEN** показан экран «Ссылка устарела» с кнопкой «Получить новую»

### Requirement: Маршрут после входа

После входа приложение SHALL открывать: подтверждение почты — если почта не подтверждена; онбординг — если он не пройден и роль `client`; иначе корневой экран роли.

#### Scenario: Почта не подтверждена

- **WHEN** вход по паролю успешен, а у пользователя почта не подтверждена
- **THEN** открыт экран ввода кода из письма

### Requirement: Код подтверждения вводится одной вставкой

Экран подтверждения SHALL принимать 6 цифр в одно поле с `textContentType(.oneTimeCode)`, проверять код автоматически после 6-й цифры (`POST /auth/verify-email`) и разрешать «Отправить повторно» через 60 секунд.

#### Scenario: Код из подсказки клавиатуры

- **WHEN** пользователь вставляет код «482913» из подсказки
- **THEN** проверка отправлена без нажатия кнопки

#### Scenario: Повторная отправка

- **WHEN** с момента отправки прошло 30 секунд
- **THEN** кнопка «Отправить повторно» недоступна и показывает оставшееся время

### Requirement: Аккаунт в процессе удаления

Ответ входа с `pending_deletion` (вход при этом успешен — сессия выдана) SHALL открывать экран «Аккаунт будет удалён {дата}» до любого другого экрана, с кнопками «Отменить удаление» (`DELETE /users/me/deletion`, затем маршрут после входа) и «Выйти» (выход с отзывом сессии).

#### Scenario: Отмена удаления

- **WHEN** пользователь с запрошенным удалением входит и нажимает «Отменить удаление»
- **THEN** удаление отменено и открыт корневой экран роли

### Requirement: Сброс пароля открывается в приложении

Universal link `/reset-password?token=` SHALL открывать экран нового пароля с проверкой политики (8–128 символов, заглавная, строчная, цифра, спецсимвол) и поддержкой предложения надёжного пароля системой (`textContentType(.newPassword)`).

#### Scenario: Слабый пароль

- **WHEN** введён пароль «qwerty12»
- **THEN** кнопка «Сохранить» недоступна, неподходящие пункты политики отмечены
