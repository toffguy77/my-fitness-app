## ADDED Requirements

### Requirement: Аккаунт через провайдера создаётся после согласий

Вход через внешнего провайдера, который создал бы новый аккаунт, SHALL не создавать аккаунт, а уводить на `/auth/consents` с одноразовым ожидающим входом; `POST /api/v1/auth/oauth/consents {consents}` с обязательными согласиями (оферта, политика, обработка персональных данных включая данные о здоровье) MUST создавать аккаунт, сохранять согласия в `user_consents` тем же кодом, что регистрация по паролю, и выдавать сессию. Куратора аккаунт получает по общему правилу `curator-access` («Регистрация не даёт права на куратора»): живому клиенту — нет, служебной учётной записи — служебный куратор.

#### Scenario: Новый пользователь через Яндекс

- **WHEN** колбэк Яндекса возвращает адрес, которого нет среди аккаунтов
- **THEN** аккаунт не создан, браузер уведён на `/auth/consents`
- **AND** после отправки обязательных согласий аккаунт создан, в `user_consents` есть три обязательных согласия

#### Scenario: Без согласия на обработку данных

- **WHEN** на `/auth/consents` отправлены оферта и политика без согласия на обработку ПДн
- **THEN** ответ `400` с кодом `validation`, аккаунт не создан

#### Scenario: Повторный вход привязанного пользователя

- **WHEN** входит пользователь, уже привязанный к провайдеру
- **THEN** экрана согласий нет, сессия выдаётся сразу
