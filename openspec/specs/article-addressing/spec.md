# article-addressing Specification

## Purpose
Определяет человекочитаемый постоянный адрес статьи (slug): как он образуется из заголовка, когда может меняться, как по нему находится публичная статья и как старые адреса по UUID постоянно перенаправляются на новые.

## Requirements

### Requirement: У статьи есть уникальный человекочитаемый slug

Каждая статья SHALL иметь slug из строчной латиницы, цифр и одиночных дефисов
длиной не более 80 символов, уникальный среди статей. При создании статьи без
явного slug он SHALL формироваться транслитерацией заголовка.

#### Scenario: Транслитерация заголовка

- **WHEN** создаётся статья с заголовком «Что такое КБЖУ и зачем его считать?»
- **THEN** её slug — `chto-takoe-kbzhu-i-zachem-ego-schitat`

#### Scenario: Совпадение заголовков

- **WHEN** создаётся статья, транслитерация заголовка которой уже занята
- **THEN** её slug получает суффикс `-2`, а при его занятости — следующий свободный номер

#### Scenario: Существующие статьи

- **WHEN** применяется миграция `090`
- **THEN** каждая существующая статья получает slug, совпадающий с результатом транслитерации её заголовка в Go, с суффиксами для повторов

#### Scenario: Явный slug неверного формата

- **WHEN** в запросе на создание или правку передан slug с кириллицей, пробелом или заглавной буквой
- **THEN** запрос отклоняется с `400`

### Requirement: Slug опубликованной статьи постоянен

Правка заголовка SHALL NOT менять slug. Явная смена slug опубликованной статьи
MUST отклоняться.

#### Scenario: Правка заголовка

- **WHEN** у опубликованной статьи меняется заголовок
- **THEN** slug остаётся прежним

#### Scenario: Смена slug опубликованной статьи

- **WHEN** у опубликованной статьи запрошена смена slug
- **THEN** запрос отклоняется с `409`, slug не меняется

#### Scenario: Смена slug черновика

- **WHEN** у черновика запрошена смена slug на свободный
- **THEN** slug меняется

### Requirement: Публичная статья доступна по slug

Публичная ручка статьи SHALL находить опубликованную статью с аудиторией `all`
как по UUID, так и по slug, и SHALL возвращать `slug` в ответе. Карточки лент
SHALL содержать `slug`, если статья имеет аудиторию `all`.

#### Scenario: Запрос по slug

- **WHEN** запрошена публичная статья по её slug
- **THEN** ответ `200` содержит статью и её slug

#### Scenario: Запрос по UUID

- **WHEN** запрошена публичная статья по UUID
- **THEN** ответ `200` содержит статью и её slug

#### Scenario: Slug статьи для клиентов куратора

- **WHEN** запрошена по slug статья с аудиторией `my_clients`
- **THEN** ответ `404`

#### Scenario: Карточка в персональной ленте

- **WHEN** персональная лента содержит статью с аудиторией `selected`
- **THEN** её карточка не содержит `slug`

### Requirement: Канонический адрес статьи строится из slug

Канонический адрес, адрес Open Graph, `mainEntityOfPage` в JSON-LD и ссылки
карточек SHALL иметь вид `/content/<slug>` для статьи со slug.

#### Scenario: Метаданные страницы

- **WHEN** отрендерена страница публичной статьи
- **THEN** её `canonical` — `https://burcev.team/content/<slug>`

#### Scenario: Ссылка карточки

- **WHEN** отрендерена карточка статьи со slug
- **THEN** ссылка ведёт на `/content/<slug>`

#### Scenario: Карточка без slug

- **WHEN** отрендерена карточка статьи без slug
- **THEN** ссылка ведёт на `/content/<uuid>`

### Requirement: Старый адрес перенаправляет постоянным редиректом

Запрос `/content/<uuid>` публичной статьи SHALL получать ответ `301` с
`Location: /content/<slug>`. Запрос `/content/<uuid>` статьи, которой нет в
публичном API, MUST пропускаться к странице без редиректа.

#### Scenario: Старая ссылка на публичную статью

- **WHEN** запрошен `/content/<uuid>` публичной статьи
- **THEN** ответ `301` на `/content/<slug>`

#### Scenario: Статья для клиентов куратора

- **WHEN** запрошен `/content/<uuid>` статьи, которой нет в публичном API
- **THEN** редиректа нет, запрос обрабатывается страницей

#### Scenario: API недоступен

- **WHEN** при запросе `/content/<uuid>` публичный API не ответил
- **THEN** редиректа нет, запрос обрабатывается страницей
