# ios-curator-hub Specification

## Purpose
Экран «Клиенты». Возможность введена изменением `ios-curator-app` (архив `openspec/changes/archive/2026-10-24-ios-curator-app`).

## Requirements

### Requirement: Сводка куратора

Экран «Клиенты» SHALL показывать четыре показателя из `GET /curator/analytics`: активные клиенты с числом требующих внимания, средний процент КБЖУ, непрочитанные с числом клиентов, задачи с просроченными и выполненными сегодня («просрочено: N · сегодня: M», вторая часть — только при M больше нуля). Динамика — упрощённая: свой средний процент КБЖУ за последние 4 недели (`?weeks=4`) без выбора периода. Ошибка загрузки любого из `analytics`, `attention`, `clients` MUST показывать «Не удалось загрузить данные» с «Повторить»; ошибка бенчмарка MUST NOT влиять на экран.

#### Scenario: Бенчмарк недоступен

- **WHEN** `GET /curator/analytics/benchmark` отвечает `500`
- **THEN** сводка, «Требуют внимания» и клиенты показаны, блока динамики нет

### Requirement: «Требуют внимания» по приоритету сервера

Блок «Требуют внимания» SHALL группировать пункты `GET /curator/attention` по клиенту в порядке наивысшего приоритета группы и показывать бейджи всех причин с их `detail`; нажатие MUST открывать адрес пункта с наивысшим приоритетом. Пустой список MUST скрывать блок.

#### Scenario: Алерт и сообщение у одного клиента

- **WHEN** у клиента есть `red_alert` и `unread_message`
- **THEN** клиент показан одной строкой с бейджами «Алерт КБЖУ» и «Сообщение»
- **AND** нажатие открывает карточку клиента, а не переписку

### Requirement: Остальные клиенты без повторов

Список «Остальные» SHALL содержать клиентов из `GET /curator/clients`, которых нет в «Требуют внимания», по имени; поиск MUST фильтровать оба списка по имени без обращения к серверу. Свайп по клиенту MUST предлагать «Написать».

#### Scenario: Поиск

- **WHEN** куратор вводит «мар»
- **THEN** в обоих списках остались только клиенты, чьё имя содержит «мар» без учёта регистра

### Requirement: Свежесть без опроса

Экран SHALL обновляться при выходе на передний план, по pull-to-refresh и по событиям WebSocket `new_message` и `unread_count_update`.

#### Scenario: Новое сообщение клиента

- **WHEN** приходит `unread_count_update`
- **THEN** показатель «Непрочитанные» и бейдж вкладки «Чаты» обновлены без перезагрузки экрана
