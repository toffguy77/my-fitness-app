# Словарь событий

22 имени. Объявлены дважды и обязаны совпадать:
`apps/api/internal/modules/analytics/dictionary.go` (сервер, источник истины) и
`apps/web/src/shared/analytics/events.ts` (клиент). Сервер отклоняет имя,
которого не знает, поэтому событие, объявленное только на клиенте, не приходит
никогда.

Если ответа на вопрос нет ни в одном из этих событий — значит данных нет.
Так и скажи, вместо того чтобы искать обходной путь.

|---|---|---|
| `landing_viewed` | открыта посадочная | `source` |
| `landing_scroll_depth` | прокрутка посадочной до порога | `depth`: 25 / 50 / 75 / 100 |
| `onboarding_started` | начат гостевой мастер | `source` |

| `registration_opened` | открыта форма регистрации | `method` |
| `registration_failed` | регистрация не удалась | `reason`, `method` |
| `magic_link_requested` | запрошена ссылка входа | — |
| `magic_link_consumed` | вход по ссылке состоялся | различает вход и создание аккаунта |

## Факты с сервера

Отправляются оттуда, где произошли. Клиентское «зарегистрировался» врёт при
обрыве связи после успешного запроса и теряется за блокировщиком, поэтому эти
события приходят только с сервера и с клиента не принимаются.

| Событие | Что означает | Свойства |
|---|---|---|
| `registered` | аккаунт создан | `method` — пароль или провайдер |
| `email_verified` | адрес подтверждён | — |
| `signed_in` | вход состоялся | `method` |
| `curator_assigned` | назначен куратор | — |
| `weekly_report_submitted` | отправлен недельный отчёт | — |
| `support_escalated` | обращение передано человеку | `reason` |
| `first_food_entry` | первая запись о еде, сделанная самим человеком | — |
| `first_curator_message` | человек написал куратору первым | — |

Последние два переехали сюда с клиента. Там они решались отметкой в
`localStorage`: отметка терялась вместе с хранилищем и отсутствовала на другом
устройстве, так что один человек считался новым дважды. А `first_food_entry`
вдобавок **не приходил ни разу за всё время** — его отправляли со свойством
`meal_type`, которого для этого имени не объявляли, и сервер отвергал его на
входе.

Записываются однажды за всё время существования учётной записи. Запись за
человека, сделанную куратором из переписки, `first_food_entry` не считает: это
работа куратора. Полученное приветствие `first_curator_message` не считает:
знакомство — это отправленное человеком сообщение.

## Жизнь в продукте

| Событие | Что означает | Свойства |
|---|---|---|
| `food_entry_created` | любая запись о еде | `method`, `meal_type` |
| `food_recognition_used` | распознавание по фото | `outcome` |
| `support_chat_opened` | открыт чат поддержки | `from` |

Разбивка по способу записи живёт здесь, на `food_entry_created`: сервер не
знает, какой вкладкой воспользовались.

## Чего в событиях нет и не будет

Проверка на приёме отклоняет свойства из списка запрещённых
(`dictionary.go`, `forbiddenProperties`): почта, имя, содержимое сообщений,
вес, рост, калории, белки-жиры-углеводы, замеры, названия блюд, дата рождения,
телефон, имя в Telegram.

Это не недосмотр. Данные продукта — о здоровье, и держать их в аналитике
означало бы обрабатывать их без отдельного основания. Вопросы вида «какие
блюда чаще записывают» или «как меняется вес у когорты» по аналитике не
решаются; за ними нужно идти в таблицы продукта, и это уже другой разговор,
с другими основаниями.

## Как склеивается воронка

`visitor_id` — идентификатор браузера, живёт в `localStorage` до регистрации.
`user_id` — появляется после. Связывает их таблица `analytics_identities`.

Без неё воронка обрывается ровно там, где интереснее всего: на переходе
«аноним → зарегистрирован». Поэтому в запросах до регистрации считай
`DISTINCT visitor_id`, после — `DISTINCT user_id`, а связь бери из
`analytics_identities`.

## Таблицы

| Таблица | Что внутри |
|---|---|
| `analytics_events` | `name`, `occurred_at`, `visitor_id`, `user_id`, `platform`, `properties` (jsonb) |
| `analytics_identities` | связь `visitor_id` ↔ `user_id` |
| `leads` | заявка: контакт, параметры, `last_step`, `capture_source`, метки кампании, `metrika_client_id` |
| `user_attribution` | откуда пришёл зарегистрировавшийся; переживает удаление заявки |
| `conversion_uploads` | очередь конверсий в рекламный кабинет, с отметкой об отправке |
