# Включение опциональных возможностей

Код каждой возможности ниже уже выкачен. Возможность выключена ровно потому,
что не заданы её переменные, и `GET /health` честно это показывает:

```bash
curl -s https://burcev.team/ready | jq .features
```

Переменные задаются в Dokploy: проект → окружение → Environment. После
сохранения нужен деплой — переменные попадают в контейнер при старте.

| prod | `BUHm2MytH3YwSdnhEhfP4` | burcev.team |
| dev | `huTmvX7ZWv6KglFd3KEvy` | new.burcev.team |

## Вход через Яндекс ID

Регистрация приложения: <https://oauth.yandex.ru/client/new>.

- **Тип**: веб-сервисы.
- **Права доступа**: «Доступ к адресу электронной почты» и «Доступ к портрету
  пользователя». Без первого мы не узнаем адрес и будем вынуждены спрашивать
  его отдельным экраном.
- **Redirect URI** — по одному приложению на среду:
  - prod: `https://burcev.team/api/v1/auth/oauth/yandex/callback`
  - dev: `https://new.burcev.team/api/v1/auth/oauth/yandex/callback`

Переменные:

```
YANDEX_OAUTH_CLIENT_ID=<ClientID>
YANDEX_OAUTH_CLIENT_SECRET=<Client secret>
```

## Вход через VK ID

Регистрация приложения: <https://id.vk.com/about/business/go>.

- **Тип**: веб-сайт.
- **Доверенный Redirect URL**:
  - prod: `https://burcev.team/api/v1/auth/oauth/vk/callback`
  - dev: `https://new.burcev.team/api/v1/auth/oauth/vk/callback`
- Адрес почты VK отдаёт не всегда. Это нормальный сценарий: продукт спросит
  адрес отдельным экраном, и созданный так аккаунт будет неподтверждённым до
  перехода по письму.

Переменные:

```
VK_OAUTH_CLIENT_ID=<ID приложения>
VK_OAUTH_CLIENT_SECRET=<Защищённый ключ>
```

Проверка обеих: `curl -s https://burcev.team/api/v1/auth/providers` должен
вернуть непустой список, а на экране входа появятся кнопки.

## Бот поддержки в Telegram

1. Создать бота у [@BotFather](https://t.me/BotFather), получить токен.
2. Придумать секрет вебхука — любая случайная строка, например
   `openssl rand -hex 32`.
3. Задать переменные и задеплоить.
4. Зарегистрировать вебхук (по одному разу на среду):

```bash
curl -X POST "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://burcev.team/api/v1/public/support/telegram",
       "secret_token":"<СЕКРЕТ>",
       "allowed_updates":["message"]}'
```

Переменные:

```
TELEGRAM_BOT_TOKEN=<токен от BotFather>
TELEGRAM_WEBHOOK_SECRET=<секрет из шага 2>
TELEGRAM_BOT_USERNAME=<имя бота без @>
NEXT_PUBLIC_TELEGRAM_BOT=<то же имя бота>
```

`NEXT_PUBLIC_TELEGRAM_BOT` подставляется в сборку фронтенда: пустое значение
означает, что ссылка «Задать вопрос в Telegram» не показывается вовсе — это
лучше, чем ссылка на бота, которого никто не поднял.

Бот отвечает строго по `docs/user-guide/`. При изменении поведения продукта
эти файлы обновляются, и в `apps/api` выполняется `make sync-knowledge` —
иначе сборка падает на `TestKnowledgeMatchesUserGuide`.

## Отслеживание ошибок (Sentry)

Нужен DSN проекта — по одному на среду, чтобы ошибки dev не смешивались с
прод-ошибками.

```
SENTRY_DSN=<DSN для бэкенда>
NEXT_PUBLIC_SENTRY_DSN=<DSN для фронтенда>
APP_VERSION=<версия сборки, попадёт в релиз Sentry>
```

`APP_VERSION` сейчас не задан ни в одной среде, поэтому `/health` показывает
`"version":"dev"` в том числе на проде. Годится любое значение, по которому
можно узнать выпуск: тег, короткий хеш коммита, дата.
