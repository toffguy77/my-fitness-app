# Цель

Реализовать iOS-приложение «Взвешено» по OpenSpec-изменениям в `openspec/changes/` и выпустить сборку в TestFlight для внутренних тестировщиков. Исполнять каждое изменение и проверять результат по его `tasks.md`.

Прежде чем начинать, прочитай `CLAUDE.md`, `docs/ios/README.md`, `docs/design-system/README.md` и все `proposal.md` и `design.md` в изменениях ниже. Макеты — холст «Взвешено · iOS»: https://claude.ai/artifact/7i8fUfu4fuwq5LSXn1ZRCL или Макеты — `docs/ios/mockups/` (таблица «экран → спека» в README; значения — из токенов, поведение — из спек). Каждый экран с макетом сверяй со своим PNG: открой PNG и скриншот симулятора рядом; расхождения по вёрстке, кроме системных элементов, — дефект.

# Порядок изменений

Каждое изменение — отдельная ветка от свежего `dev` и отдельный PR в `dev`. Следующее начинай только после того, как предыдущее влито и выкачено на dev-стенд https://new.burcev.team.

1. `web-fixes-before-ios` — исправления веба и общие серверные части. Без него не начинать ничего другого.
2. `ios-native-session` — сессия приложения, Sign in with Apple, нативный OAuth, AASA, `GET /api/v1/config`.
3. `ios-app-foundation` — проект `apps/ios`, токены → Swift, API, сессия, офлайн-очередь, `Idempotency-Key`, CI.
4. `ios-push-notifications` — APNs.
5. `healthkit-sync` — Здоровье.
6. `ios-client-app` — экраны клиента.
7. `ios-curator-app` — экраны куратора.
8. `ios-system-surfaces` — виджеты, Пункт управления, Siri.

Бэкенд-части изменений 2, 4 и 5 можно делать параллельно с 3, если они не трогают одни и те же файлы. Порядок PR при этом сохраняется.

# Как работать с каждым изменением

1. Синхронизация:
```bash
   git checkout dev && git pull --ff-only && git checkout -b feat/<имя-изменения>
```
2. Используй навык `openspec-apply-change`. Выполняй задачи из `tasks.md` по порядку и отмечай `- [x]` только после того, как прошла проверка, указанная в самой задаче.
3. Требования из `specs/**/spec.md` — это контракт. Каждый сценарий WHEN/THEN покрывается автотестом. Если требование неверно или невыполнимо, не обходи его молча: исправь спеку в том же PR, объясни причину в описании и прогони `openspec validate <имя> --strict`.
4. Перед PR — полный набор проверок:
   - веб: `cd apps/web && npm run lint && npm run type-check && npx jest`;
   - Go: `cd apps/api && go test ./...`, `UPDATE_GOLDEN=1 go test ./internal/router/` с просмотром diff;
   - корень: `node scripts/check-api-contract.mjs`, `node scripts/check-codebase-integrity.mjs`, `npm run tokens:check`, `npm run tokens:test`;
   - iOS (начиная с изменения 3): `cd apps/ios && xcodegen generate && swiftlint --strict && xcodebuild test -scheme Vzvesheno-Dev -destination 'platform=iOS Simulator,name=iPhone 16'`;
   - Playwright: весь набор, 0 failed.
5. PR в `dev`:
   - описание на русском: что сделано, как проверено, миграции;
   - в конце — строки атрибуции Claude Code;
   - дождись зелёного CI, PR не сливай — сливаю я;
   - после мержа проверь выкат на new.burcev.team по пунктам «выкат» из `tasks.md`.
6. После выката изменения на прод: `openspec archive <имя>`, отдельным коммитом.

# Обязательные правила проекта (из CLAUDE.md)

- **Миграции.** Номер выбирай по `SELECT max(version) FROM schema_migrations` на dev **и** на проде, а не по файлам в ветке.
- **Маршрут с id.** Нужна запись в `protectedRoutes` (`authorization_matrix_test.go`) с осознанно выбранной защитой.
- **Цвета.** Только роли из `packages/design-tokens`. В Swift цвет литералом запрещён (правило `ds_color_literal`). После правки токенов коммить вместе с `dist/` и `dist/ios/`.
- **Изменение поведения.** Обнови `docs/user-guide/` и выполни `make sync-knowledge`.
- **Имена обязательных проверок CI не меняй.** Задача `ios` в CI новая и необязательная.
- **Секреты в git не попадают.** Сюда относятся `.p8`, пароли и токены. Они хранятся только в Dokploy и в связке ключей macOS.
- **Коммиты** — conventional commits, `--max-warnings 0`. Подавлять предупреждения можно только точечно и с причиной.

# Данные для iOS

- Bundle id: `team.burcev.app` для прода, `team.burcev.app.dev` для dev. Если `.dev` ещё не заведён, заведи его или спроси меня.
- APNs: ключ «Weighted», Key ID `743P3Y36VM`. Сам `.p8` — в реро.
- Минимальная iOS — 18. Интерфейс на русском, строки в String Catalog с формами множественного числа.
- Аналитика — только `POST /api/v1/public/analytics/events`, без сторонних SDK и без ATT.
- В приложении нет цены куратора, заявки на него и ссылок на оплату (App Review 3.1.1(a)); основание для оплаты на сайте — 3.1.3(d).

# Где остановиться и спросить меня

Не угадывай и не обходи — остановись и спроси, если нужно:
- Team ID, ключ App Store Connect API (Issuer ID, Key ID, `.p8`) или ключ Sign in with Apple;
- запись приложения в App Store Connect;
- секреты в Dokploy для dev или прода: `APPLE_*`, `APNS_*`, `IOS_MIN_SUPPORTED_VERSION`;
- регистрация домена отправителя в Apple Private Email Relay;
- решение, которое меняет продукт или противоречит спеке или правилам App Store;
- деструктивное действие: удаление данных, force-push, изменение прав репозитория.

Всё остальное делай сам. Когда ждёшь меня, продолжай то, что от ответа не зависит.

# Выпуск в TestFlight

Выпускать после того, как изменения 1–8 влиты, выкачены на прод и `IOS_MIN_SUPPORTED_VERSION` задан.

1. Версия `1.0.0`, номер сборки — из `git rev-list --count HEAD` или по времени. Вычисляй его в `project.yml`, руками не правь.
2. Сборка и загрузка через fastlane (`apps/ios/fastlane/Fastfile`, lane `beta`):
   - подпись — автоматическая в Xcode или `match`, выбери одно и опиши в `apps/ios/README.md`;
   - `build_app(scheme: "Vzvesheno-Prod", export_method: "app-store")`;
   - `upload_to_testflight` с ключом App Store Connect API из переменных окружения, без ввода пароля Apple ID;
   - группа внутренних тестировщиков, заметки сборки — на русском.
3. App Store Connect:
   - ярлыки приватности: здоровье и фитнес, фото, почта; данные об использовании — без отслеживания;
   - текст для App Review про куратора (3.1.3(d)) и демо-аккаунт клиента с доступом к куратору. Демо-аккаунт — служебная учётка по правилам «Служебные учётки» из `CLAUDE.md`.
4. Смоук-проверка на реальном iPhone из TestFlight, на проде:
   - вход через Apple → согласия → онбординг → «Сегодня»;
   - запись еды штрихкодом и по фото → остаток уменьшился → запись видна в вебе;
   - вес из Здоровья пришёл без открытия приложения;
   - пуш о сообщении куратора → ответ из уведомления → ответ виден у куратора в вебе;
   - «+ стакан» из виджета в режиме полёта доставлен после появления сети ровно один раз;
   - куратор: «Ввести КБЖУ» по фото клиента → запись у клиента с пометкой «Добавлено куратором»;
   - выход → виджет не показывает данные, пуши на устройство не приходят.

Каждый пункт — ✅ или ❌ с описанием и скриншотом.
