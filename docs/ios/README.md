# Взвешено для iPhone: экраны и функциональность

Здесь веб-приложение разобрано на экраны, у каждого описана функциональность и
то, как она переносится в iOS. Требования, по которым приложение строится и
проверяется, — в OpenSpec:

| Изменение | Что внутри |
|---|---|
| `openspec/changes/ios-native-session` | Бэкенд: сессия для приложения (refresh в Keychain), Sign in with Apple, нативный OAuth, AASA, `GET /api/v1/config` |
| `openspec/changes/ios-push-notifications` | Бэкенд: устройства APNs, отправка, действия в уведомлениях, адресация экранов |
| `openspec/changes/healthkit-sync` | Бэкенд + iOS: импорт шагов, веса и тренировок из Здоровья, запись еды и воды в Здоровье |
| `openspec/changes/ios-app-foundation` | iOS: проект, токены дизайн-системы в Swift, сеть, сессия, ошибки, офлайн-очередь, оболочка по роли, CI |
| `openspec/changes/ios-client-app` | iOS: экраны клиента |
| `openspec/changes/ios-curator-app` | iOS: экраны куратора |
| `openspec/changes/ios-system-surfaces` | iOS: виджеты, Пункт управления, App Intents и Siri |

Макеты — холст Design «Взвешено · iOS»
(https://claude.ai/artifact/7i8fUfu4fuwq5LSXn1ZRCL, открывается у владельца
и у тех, с кем им поделились): светлая и тёмная тема, клиент, куратор,
системные поверхности.

Решения, принятые для первой версии:

- одно приложение для клиента и куратора, интерфейс выбирается по роли из
  `GET /auth/me`; суперадмин получает только «Заявки» и «Обращения», а
  управление контентом и админка остаются в вебе;
- SwiftUI, минимальная версия iOS 18; на iOS 26 — Liquid Glass системных
  панелей без отдельного кода;
- цвета, шрифты и отступы — из `packages/design-tokens` (тот же источник, что
  у веба); шрифты Literata и Golos Text встраиваются в приложение и
  масштабируются с Dynamic Type;
- цена работы с куратором и ссылки на оплату в приложении не показываются
  (App Store Guideline 3.1.1); клиент без доступа видит экран без цены и
  может написать в поддержку. **Открытый вопрос владельцу продукта** —
  принимаем ли заявку на куратора из приложения (см. `ios-client-app/design.md`).

## Навигация

### Клиент

Таббар из четырёх вкладок, над ним — аксессуар «Записать еду»
(`tabViewBottomAccessory`; на iOS 18 — плавающая панель того же вида).

| Вкладка | Веб | Корневой экран |
|---|---|---|
| Сегодня | `/dashboard` | дашборд дня |
| Дневник | `/food-tracker` | дневник питания |
| Куратор | `/chat` | переписка с куратором |
| Статьи | `/content` | лента |

В навигационной панели «Сегодня»: колокольчик → «Уведомления», аватар →
«Профиль». Вкладка «Тренировка» веба (выключена) не переносится: тренировка —
карточка на «Сегодня», данные приходят из Здоровья.

Аксессуар «Записать еду» виден на «Сегодня», «Дневнике» и «Статьях»; в чате
его место занимает поле сообщения.

### Куратор

| Вкладка | Веб | Корневой экран |
|---|---|---|
| Клиенты | `/curator` | сводка, «Требуют внимания», все клиенты |
| Чаты | `/curator/chat` | список переписок |
| Заявки | `/curator/leads` | очередь заявок |
| Обращения | `/curator/support` | очередь обращений поддержки |

«Контент» куратора остаётся в вебе: редактор Markdown, обложки, импорт `.md` и
предпросмотр — работа за компьютером. В профиле куратора — ссылка «Статьи — в
веб-версии».

## Экраны клиента

Для каждого экрана: что он делает, из чего состоит, откуда берёт данные, какие
у него состояния и что меняется в iOS. Пути API — без префикса `/api/v1`.

### Вход и регистрация

**Веб:** `/auth`, `/auth/email`, `/auth/link`, `/auth/link/consume`,
`/auth/complete`, `/auth/verify-email`, `/forgot-password`, `/reset-password`.

**Функциональность.**

- Вход по паролю: почта, пароль, «Запомнить меня на 30 дней» →
  `POST auth/login`. В приложении «запомнить» включено всегда: сессия живёт
  в Keychain.
- Ссылка на почту: `POST auth/magic-link/request {email, consents}`, ответ
  одинаковый для известных и новых адресов; ссылка живёт 15 минут.
- Провайдеры: Яндекс ID и VK ID (`GET auth/providers`). В iOS добавляется
  **Вход с Apple** — обязателен при наличии сторонних входов (Guideline 4.8).
- Регистрация с паролем: 4 согласия (оферта, политика, ПДн включая данные о
  здоровье — обязательны; маркетинг — нет), политика пароля 8–128 символов,
  заглавная, строчная, цифра, спецсимвол.
- Подтверждение почты: 6 цифр, проверка на 6-й цифре, «Отправить повторно»
  через 60 с, 5 попыток на код.
- Сброс пароля: письмо со ссылкой на час, раз в час.
- Аккаунт в процессе удаления: экран «Аккаунт будет удалён» с «Отменить
  удаление» (`DELETE users/me/deletion`) и «Продолжить без отмены» (в
  приложении — «Выйти»).
- После входа: почта не подтверждена → подтверждение; онбординг не пройден →
  онбординг; иначе → «Сегодня» (у куратора — «Клиенты»).

**В iOS.**

- Вход с Apple — `ASAuthorizationAppleIDProvider`, сервер принимает
  identity token.
- Яндекс и VK — `ASWebAuthenticationSession` с возвратом на universal link и
  одноразовым кодом обмена (сейчас вход заканчивается веб-страницей
  `/auth/complete` и cookie, которые до приложения не доходят).
- Ссылка из письма и ссылка сброса открывают приложение (universal links на
  `/auth/link/consume` и `/reset-password`).
- Код из письма — `textContentType(.oneTimeCode)`; пароль — автозаполнение
  связкой ключей (`webcredentials`).
- Согласия для нового аккаунта показываются до его создания: вход через
  Apple, Яндекс или VK, который создал бы аккаунт, сначала возвращает
  `needs_consents`, и аккаунт появляется только после согласий.

### Онбординг

**Веб:** `/onboarding` (под входом), гостевой онбординг и
`/kalkulyator-kbzhu` (публичные).

**Функциональность (под входом).** Два шага:

1. «Настройки»: язык, единицы, часовой пояс → `PUT users/settings`.
2. «Тело и цели»: дата рождения, пол, текущий вес, рост, активность, цель; все
   поля необязательны → `PUT users/settings` и `PUT users/onboarding/complete`.

**В iOS.**

- Часовой пояс и язык предзаполняются с устройства.
- Третий, необязательный шаг — «Подключить Здоровье» (тот же экран, что в
  профиле).
- Текущий вес сохраняется как замер веса (`POST dashboard/daily`, тип
  `weight`), а не как целевой — в вебе это ошибка (см. «Не переносим»).
- Гостевой онбординг и калькулятор в приложение не переносятся: приложение
  открывается со входа, а расчёт нормы делает сервер после «Тела и целей».

### Сегодня

**Веб:** `/dashboard`. **Макеты:** «Клиент · Сегодня», «Сегодня, тёмная тема».

**Блоки сверху вниз.**

1. Заголовок с датой; колокольчик со счётчиком непрочитанных
   (`GET notifications/unread-counts`); аватар.
2. Неделя Пн–Вс: у дня три точки — питание, вес, активность
   (`GET dashboard/week`). Тап по дню переключает «Сегодня» на этот день.
3. Питание: остаток ккал главным числом, «съедено X из Y» подписью; остаток
   по Б/Ж/У в граммах, если заданы все три нормы. При превышении — «+N ккал
   сверх нормы», цвет не меняется. Норма — активный план куратора
   (`GET dashboard/weekly-plan`), иначе расчётная (`GET nutrition-calc/targets`).
   Без нормы — «Норма не посчитана» с тем, чего не хватает, и кнопками
   «Заполнить профиль» / «Записать вес».
4. Куратор: имя, последнее сообщение, непрочитанные → вкладка «Куратор».
   Без доступа — карточка «Работа с куратором» без цены (см. решения выше).
5. Шаги, вода, вес, тренировка — карточки 2×2:
   - шаги: значение и цель (`weeklyPlan.stepsGoal`, иначе 10 000); источник
     «из Здоровья», ручной ввод — по тапу;
   - вода: «N из M стаканов», кнопка «+» (`POST food-tracker/water`); если
     куратор не задал цель (`enabled=false`), карточки нет;
   - вес: последнее значение, изменение за неделю, источник; ввод 0,1–500 кг;
   - тренировка: длительность и тип, «+N ккал к норме»; ввод вручную — типы
     и длительность 1–600 мин.
6. «Первая неделя» (чек-лист из `GET dashboard/onboarding`, пока `active`).
7. «Задачи от куратора» (`GET dashboard/tasks`): отметка
   `POST dashboard/tasks/:id/complete`; задача-тренировка просит тип и
   длительность.
8. «Фото недели»: в субботу и воскресенье без фото — напоминание; камера или
   «Фото» → `POST dashboard/photo-upload`.
9. «Отправить недельный отчёт» — только в воскресенье текущей недели
   (`POST dashboard/weekly-report`); при отказе сервер перечисляет, чего не
   хватает (питание ≥5/7, вес ≥5/7, фото).
10. «Планка недели» (план куратора с комментарием) и «Неделя по калориям»
    (`GET nutrition-calc/history?days=7`) — ниже, после первой недели.
11. Прогресс за 4 недели (`GET dashboard/progress?weeks=4`) — после первой
    недели.

**Состояния:** загрузка — скелетоны карточек; нет сети — данные из кэша и
плашка «Нет подключения»; изменения сохраняются в очередь и уходят при
появлении сети.

**В iOS.**

- Обновление — pull-to-refresh и возврат приложения на передний план вместо
  опроса каждые 30 с.
- Шаги, вес и тренировки приходят из Здоровья (`healthkit-sync`).
- Отметка задачи и «+ стакан» доступны и из уведомления, и из виджета.
- Хаптик на «+ стакан», отметку задачи и достижение цели.

### Записать еду

**Веб:** окно «Добавить запись» в `/food-tracker`, быстрые кнопки дашборда.
**Макеты:** «Записать еду (лист)», «Штрихкод», «Еда по фото».

**Функциональность.**

- Лист с выбором приёма пищи (по часу: 5–10 завтрак, 11–15 обед, 17–21 ужин,
  иначе перекус) и четырьмя способами:
  1. Поиск: `GET food-tracker/search?q=&limit=20&offset=`, задержка 300 мс; при
     пустой строке — «Недавние» (`GET food-tracker/recent`) и «Избранное»
     (`GET food-tracker/favorites`, звезда — `POST`/`DELETE`).
  2. Штрихкод: `GET food-tracker/barcode/:code`, ручной ввод 8–14 цифр.
  3. Фото: `POST food-tracker/recognize` (до 3 в день по умолчанию); позиции с
     уверенностью; вес не подставляется сам — «оценка N г» и «Подставить»;
     пакетное добавление; низкая уверенность → «Найти».
  4. Вручную: название, бренд, ккал на 100 г, Б/Ж/У, порция →
     `POST food-tracker/user-foods`.
- Порция: граммы 1–2000 (быстрые 100/150/200/250), мл, порции 0,5–10.
- Добавление → `POST food-tracker/entries`.

**В iOS.**

- Штрихкод — `DataScannerViewController` (VisionKit): EAN-13/EAN-8/UPC
  распознаются без кнопки, фонарик, ручной ввод — запасной путь; на
  устройствах без поддержки — AVFoundation.
- Фото — камера или PhotosPicker; HEIC переводится в JPEG и ужимается до
  1280 px на устройстве (сервер HEIC отклоняет).
- Поиск — с 2 символов (руководство пользователя обещает 2, веб требует 3).
- Вес порции — колесо и быстрые значения; результат появляется в дневнике
  сразу, синхронизация — в фоне.
- Тот же лист открывается из аксессуара, виджета, Пункта управления, кнопки
  «Действие» и App Intent.

### Дневник

**Веб:** `/food-tracker`. **Макет:** «Клиент · Дневник».

**Функциональность.**

- День с переключением ‹ › и календарём; итог «осталось / съедено из нормы»,
  макросы, подпись источника нормы («Рассчитано автоматически» / «План
  куратора» и «+N ккал за тренировку»).
- Приёмы пищи: Завтрак, Обед, Ужин, Перекус; «Итого», «Нет записей»,
  «Добавить». Тап по записи — правка (приём, порция, время, название, КБЖУ)
  → `PUT food-tracker/entries/:id`; удаление → `DELETE`.
- «Сохранить как своё» → `POST food-tracker/user-foods/clone`.
- Вода: «−» и «+».
- Вкладка «Нутриенты»: категории (витамины, минералы, липиды, клетчатка,
  растительность), «Настроить список», «Добавить рекомендацию», детали
  нутриента (`GET food-tracker/recommendations…`).
- Данные дня: `GET food-tracker/entries?date=`, `GET food-tracker/water?date=`,
  `GET nutrition-calc/targets?date=`.

**В iOS.**

- Удаление — свайпом влево; копирование записи на другой день — из
  контекстного меню.
- Дата из ссылки (`?date=`) учитывается (веб её игнорирует).
- Вкладку «Чат» из окна добавления не переносим — в вебе это заглушка.

### Куратор (чат клиента)

**Веб:** `/chat`. **Макет:** «Клиент · Куратор (чат)».

**Функциональность.**

- Доступ: `GET conversations/access` → `{allowed, expired, expires_at}`. Нет
  доступа — экран без цены; доступ истёк — история только для чтения.
- Переписка: `GET conversations`, первая; сообщения
  `GET conversations/:id/messages?limit=50&cursor=`; отправка
  `POST conversations/:id/messages`.
- Вложения до 10 МБ: `POST conversations/:id/upload`, затем сообщение
  `image` или `file`.
- Карточка «КБЖУ записано» (тип `food_entry`) — создаёт куратор.
- «Печатает» — WS `typing`; прочтение — `POST conversations/:id/read` при
  показе сообщений.

**В iOS.**

- WebSocket (`POST auth/ws-ticket`, `/ws?ticket=`) — пока приложение
  открыто; в фоне — пуш с ответом прямо из уведомления.
- Вложения: камера, PhotosPicker, Файлы; просмотр — QuickLook; сохранение и
  «Поделиться» — share sheet.

### Статьи

**Веб:** `/content`, `/content/[id]`. **Макет:** «Клиент · Статьи».

**Функциональность.**

- Лента `GET content/feed?category&limit&offset`, категории Все / Питание /
  Тренировки / Рецепты / Здоровье / Мотивация / Общее, подгрузка.
- Статья: `GET content/feed/:id` (личная) или `GET public/content/:ref`;
  Markdown + GFM, автор.

**В iOS.**

- Markdown разбирается `swift-markdown` и рисуется своими представлениями
  SwiftUI на токенах: заголовки, списки, таблицы, изображения.
- «Поделиться» — канонический адрес `https://burcev.team/content/<slug>`.
- Ссылки на статьи открывают приложение (universal links на `/content/*`).
- Призыв статьи «Рассчитать мою норму» в приложении ведёт в «Тело и цели», а
  не на публичный калькулятор.

### Уведомления

**Веб:** выпадающий список колокольчика и `/notifications`.

**Функциональность.**

- Вкладки «Основные» / «Контент» со счётчиками; список
  `GET notifications?category=&limit&offset`; прочтение
  `POST notifications/:id/read` после 2 с видимости; «Прочитать все»
  `POST notifications/mark-all-read {category}`.
- Тап открывает экран, на который указывает уведомление.

**В iOS.**

- Экран открывается тапом по колокольчику; системные уведомления
  дополняют его, а не заменяют.
- Открытие экрана не помечает «Контент» прочитанным (в вебе выпадающий
  список делает это сам).
- Переход — по типу и идентификаторам уведомления (`ios-push-notifications`),
  веб-путь — только запасной.

## Экраны куратора

### Клиенты

**Веб:** `/curator`. **Макет:** «Куратор · Клиенты».

**Функциональность.**

- Сводка: активные клиенты и сколько требуют внимания, средний % КБЖУ,
  непрочитанные, задачи (просрочено / сегодня) — `GET curator/analytics`.
- «Требуют внимания» — `GET curator/attention`, сгруппировано по клиенту,
  порядок по наивысшему приоритету: алерт КБЖУ (<50% или >120% плана),
  просроченная задача, нет активности 2 дня, сообщение, ожидает отзыв,
  неполный профиль. Тап — туда, куда ведёт пункт с наивысшим приоритетом.
- «Остальные» — `GET curator/clients`, без тех, кто уже в «Требуют внимания»,
  по имени; на карточке % КБЖУ, вес и тренд, вода, бейджи.
- Динамика 4/8/12 недель против платформы (`GET curator/analytics/benchmark`) —
  ниже, неблокирующая.

**В iOS.**

- Поиск по имени (`.searchable`), pull-to-refresh.
- Свайп по клиенту: «Написать».
- Пуш куратору при эскалации, новом сообщении и запросе куратора.

### Карточка клиента

**Веб:** `/curator/clients/[id]?tab=`. **Макет:** «Куратор · Карточка клиента».

**Функциональность.**

- Шапка: имя, возраст, пол, активность, цель, «Написать»; «Подробнее» — рост,
  вес, часовой пояс.
- **Обзор** (`GET curator/clients/:id?days=7`): серия, тренд веса, алерты дня,
  недельный план, цели против факта за неделю, дневник по дням (3 дня сразу,
  остальные — «Ранее»), вес с целью (правка 20–500 →
  `PUT …/target-weight`), шаги, вода и цель по воде 1–30 или «Убрать»
  (`PUT …/water-goal`), тренировки, фото недели, оповещения клиента
  (`GET …/notices`).
- **План** (`GET …/weekly-plans`): текущий, история, создание и правка
  (ккал, Б/Ж/У, даты, комментарий), удаление с подтверждением.
- **Задачи** (`GET …/tasks?status=`): активные / завершённые / просроченные;
  создание и правка (название, тип, дедлайн, описание, повторение, дни).
- **Отчёты** (`GET …/weekly-reports`): «Дать обратную связь» — оценки
  питание / активность / вода, комментарии, «Фото загружено», итог
  (обязателен), рекомендации → `PUT …/weekly-reports/:reportId/feedback`.

**В iOS.**

- Вкладки — сегментированный переключатель; формы плана, задачи и отзыва — листы.
- Фото недели открываются на весь экран с жестом масштабирования.

### Чаты и переписка

**Веб:** `/curator/chat`, `/curator/chat/[clientId]`. **Макеты:**
«Куратор · Переписка», «КБЖУ по фото (лист)».

**Функциональность.**

- Список `GET conversations`: непрочитанные сверху, затем по времени;
  превью «Фото» / «Файл» / «КБЖУ запись».
- Переписка — как у клиента; на фото клиента — «Ввести КБЖУ»: блюдо, приём,
  вес, ккал, Б/Ж/У → `POST conversations/:id/messages/:msgId/food-entry`;
  запись появляется в дневнике клиента с пометкой «Добавлено куратором».
- Ответы из Telegram-группы приходят в ту же переписку.

**В iOS.**

- Экран открывается по клиенту напрямую — нужна ручка «переписка по
  clientId» вместо поиска в общем списке; «не найдено» — явное состояние.
- Ответ из пуша, вложения камерой.

### Заявки

**Веб:** `/curator/leads`. **Макет:** «Куратор · Заявки».

**Функциональность.**

- `GET curator/leads?limit=50[&include_handled=true]` — необработанные от
  старых к новым, порядок задаёт сервер.
- Карточка: имя или «Без имени», почта, где остановился, параметры, сколько
  ждёт, «напоминание отправлено», источник (utm → referrer → «неизвестен»).
- «Отметить обработанной» → `POST curator/leads/:id/handled`; 409
  `lead_already_claimed` — тост с причиной.
- Без согласия на связь — плашка «Согласия на связь нет — писать нельзя» и
  **никакой** кнопки «Написать».
- «Открыть переписку» — если есть `conversation_id`.

**В iOS.**

- «Написать» — системный редактор письма (`MFMailComposeViewController`),
  при его отсутствии — `mailto:`.

### Обращения

**Веб:** `/curator/support`. **Макет:** «Куратор · Обращение».

**Функциональность.**

- `GET curator/support/conversations[?status=]` — эскалированные первыми;
  статусы «Ждёт ответа», «Отвечает бот», «Закрыто»; причина эскалации.
- Тред `GET …/:id`: связь с заявкой, сообщения «Пользователь» / «Оператор» /
  «Бот»; ответ `POST …/:id/reply {text}` уходит в Telegram; «Закрыть
  обращение» `POST …/:id/close`.

**В iOS.**

- Пуш при эскалации; pull-to-refresh (в вебе обновление только ручное).
- Признак «Не доставлено в Telegram · Повторить» у ответа — нужен в ответе
  API (спека `support-conversation-bridge` его требует, интерфейс веба его не
  показывает).

## Не переносим из веба

Найдено при разборе; в iOS поведение сразу правильное. Веб чинится
отдельными изменениями.

1. Онбординг сохраняет «Текущий вес» как `target_weight`.
2. Дневник игнорирует `?date=` из быстрой записи дашборда.
3. Вкладка «Чат» в окне добавления еды — заглушка.
4. `CuratorFeedbackSection` на дашборде никогда не рисуется: `reportId` не
   передаётся. В iOS отзыв куратора на отчёт открывается из уведомления
   `feedback_received` (пуш и список уведомлений несут id отчёта).
5. «Выйти» в профиле не вызывает `POST auth/logout`.
6. Открытие колокольчика помечает весь «Контент» прочитанным.
7. Поиск продуктов начинается с 3 символов вместо 2.
8. В переписке куратора «разговор не найден» оставляет вечную «Загрузку…».
9. Переключатель Apple Health — заглушка.
10. Регистрация через Яндекс или VK, по коду `modules/auth/oauth_service.go`,
    не сохраняет согласия (у формы регистрации они обязательны). Нужно
    подтвердить и исправить в вебе; в приложении аккаунт создаётся только после
    согласий (`needs_consents`).
