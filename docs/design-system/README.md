# Дизайн-система BURCEV — «Коуч + Ясность»

Единый источник решений о том, как выглядит и ведёт себя интерфейс BURCEV на
вебе, а затем на iOS и Android. Значения живут в
[`packages/design-tokens`](../../packages/design-tokens), компоненты — в
[`apps/web/src/shared/components/ui`](../../apps/web/src/shared/components/ui),
живой справочник — на странице `/design-system` (`make dev-web` →
`http://localhost:3070/design-system`).

Направление выбрано из трёх вариантов (макеты на канвасе «BURCEV — дизайн-система»):
основа — **«Коуч»** (куратор и план дня первыми, тёплая бумага, засечки), из
**«Ясности»** взяты остаток в граммах по каждому макросу, панель «Поиск · Код ·
Фото» и недельные точки, из **«Пульса»** — запись еды в одно касание прямо с
карточки питания на дашборде.

---

## 1. Принципы

1. **Куратор — голос, а не виджет.** Всё, что говорит человек (сообщение
   куратора, подсказка, план дня), — на тёмной поверхности `coach` и
   засечками. Счётчики и цифры — гротеском на светлой бумаге. Отличие продукта
   от бесплатного счётчика видно с первого взгляда.
2. **Остаток важнее доли.** Главное число — сколько ещё можно (944 ккал,
   49 г белка). «Съедено из нормы» — подпись. Проценты на экран не выводятся.
3. **Цвет опознаёт, а не оценивает** ([openspec macro-colour-system](../../openspec/specs/macro-colour-system/spec.md)).
   Белки, жиры, углеводы всегда своего цвета при любой доле от нормы.
   Превышение — словом и знаком «+», не перекраской. «Мимо нормы» —
   единственная оценочная роль (`warning`).
4. **Одно главное действие на экран.** Терракота (`primary`) — только у него и
   у точки активного раздела. Остальные действия — контуром или без подложки.
5. **Меньше касаний до записи.** Поиск, фото и штрихкод доступны в одно
   касание с дашборда и из дневника; приём пищи угадывается по времени.
6. **Доступно по построению.** Цель нажатия ≥ 44 px, текст ≥ 4.5:1 к фону
   (проверяется сборкой токенов), поле ввода 16 px (iOS не масштабирует
   страницу), уважается `prefers-reduced-motion`, у иконок-кнопок есть
   `aria-label`, у полос и шкал — названия для экранного диктора.
7. **Без нормы — без доли.** Если норма не посчитана, показывается съеденное
   числом и приглашение её посчитать. Шкалы и остатки не рисуются: их нечем
   заполнить честно.

## 2. Как устроено

```
packages/design-tokens/tokens/          ← источник (W3C Design Tokens, DTCG)
  primitive/color.json                  палитра: sand, umber, night, terracotta, blue, amber, sage, rust, red
  base.json                             шрифты, шкала текста, отступы, радиусы, размеры, движение
  semantic/light.json, dark.json        роли цвета и тени для каждой темы
        │  npm run tokens:build  (scripts/build.mjs)
        ▼
packages/design-tokens/dist/
  tokens.css     --ds-* переменные; тёмная тема по prefers-color-scheme и [data-theme="dark"]
  tailwind.css   @theme для Tailwind v4: bg-surface, text-fg-muted, rounded-card, type-title-2…
  tokens.js/.d.ts  color.* (CSS-переменные для SVG/recharts), values.light/dark (сырые значения)
  tokens.json    развёрнутые значения обеих тем — для iOS/Android
```

Три слоя: **палитра** (сырые значения, в коде не используются) → **роли**
(`color.bg.surface`, `color.macro.protein` — то, на что ссылается интерфейс) →
**компоненты**. Тема меняет только роли; компонент про тему не знает, поэтому
`dark:` в разметке не нужен.

Сборка падает, если:
- ссылка `{palette.x}` ведёт в пустоту;
- у светлой и тёмной темы разный набор ролей;
- пара «текст на фоне» не держит контраст (список пар — `CONTRAST_PAIRS` в `build.mjs`).

`npm run tokens:check` (в CI — шаг «Check design tokens») ничего не пишет и падает,
если `dist/` отстал от источника.

**Палитра Tailwind по умолчанию отключена** (`--color-*: initial`): классов
`gray-500` или `blue-600` в проекте нет. ESLint (`no-restricted-syntax` в
`eslint.config.mjs`) запрещает такие классы и цвет литералом (`'#3b82f6'`) в
`apps/web/src`.

## 3. Цвет — роли

| Tailwind | Роль | Назначение |
|---|---|---|
| `bg-canvas` | `color.bg.canvas` | фон экрана |
| `bg-surface` | `color.bg.surface` | карточки, списки, поля ввода |
| `bg-subtle` | `color.bg.subtle` | вторичная заливка: полоса нормы, наведение, неактивное |
| `bg-nav` | `color.bg.nav` | нижняя навигация и шапка поверх прокрутки (с `backdrop-blur`) |
| `bg-scrim` | `color.bg.scrim` | затемнение под модальными окнами |
| `text-fg` | `color.fg.default` | основной текст и иконки |
| `text-fg-muted` | `color.fg.muted` | вторичный текст: подписи, единицы |
| `text-fg-subtle` | `color.fg.subtle` | третичный: метки секций, неактивные вкладки (≥ 4.5:1) |
| `text-fg-inverse` | `color.fg.inverse` | текст на инвертированной заливке `bg-fg` (выбранный день) |
| `border-line` / `border-line-strong` | `color.line.*` | границы и разделители / контурные кнопки, активная вкладка |
| `bg-primary` / `text-on-primary` | `color.primary.*` | главное действие экрана, бренд (терракота) |
| `bg-primary-soft` | `color.primary.soft` | подложка акцента |
| `bg-coach` / `text-on-coach` / `text-on-coach-muted` | `color.coach.*` | голос куратора, подсказки, панель быстрого ввода, уведомления |
| `bg-track` | `color.track` | незаполненная часть полос и дуг |
| `bg-protein` `bg-fat` `bg-carbs` | `color.macro.*` | заливка нутриента (полосы, сегменты, точки) |
| `text-protein-fg` `text-fat-fg` `text-carbs-fg` | `color.macro.*-fg` | подпись нутриента текстом (темнее заливки ради контраста) |
| `bg-water` | `color.macro.water` | вода |
| `success` `warning` `danger` `info` (+ `-fg`, `-soft`) | `color.status.*` | состояния. `warning` — «мимо нормы», превышение |
| `ring-focus` | `color.focus` | кольцо фокуса клавиатуры |

В коде, где нужен цвет значением (SVG, recharts): `import { color } from
'@burcev/design-tokens'` → `color.protein` (= `var(--ds-color-macro-protein)`,
переключается с темой). Для графиков — `@/shared/charts/chartTheme`. Где
CSS-переменных нет (картинка OG, `global-error`) — `values.light[...]`.

Цвета нутриентов в коде — только через `@/shared/constants/macros`
(`MACRO_COLORS`, `MACRO_TEXT_COLORS`).

## 5. Пространство, форма, движение

- **Сетка 4 pt**: шаги 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64.
  Боковое поле экрана на телефоне — 20 px (`px-screen-x`).
- **Радиусы**: `rounded-field` 10 (поля), `rounded-tile` 14 (плитки, вложенные
  карточки), `rounded-card` 18 (карточки экрана), `rounded-sheet` 28 (шторки и
  модальные окна), `rounded-full` (кнопки, чипы). Старые `rounded-lg`/`rounded-xl`
  перенастроены на ту же шкалу.
- **Тени**: только у того, что лежит над экраном — `shadow-float` (панель
  быстрого ввода), `shadow-overlay` (модальные окна, меню). Карточки отделяются
  линией 1 px, без тени.
- **Размеры**: цель нажатия `size.touch` 44, кнопка и поле `size.control` 48,
  нижняя навигация 64 + safe area, колонка контента ≤ 640 (`max-w-content`).
- **Движение**: 120 мс (нажатие), 200 мс (смена состояния), 320 мс
  (заполнение, шторки); кривая `ease-standard` = `cubic-bezier(0.2, 0, 0, 1)`.
  При `prefers-reduced-motion` анимации выключаются глобально.

## 7. Экраны-образцы

**Дашборд** (`app/dashboard/page.tsx`): приветствие засечками по времени суток
→ карточка куратора (`coach`, цитата последнего сообщения) → питание (дуга с
остатком ккал, остаток по макросам, запись в одно касание) → шаги, вода,
тренировка → вес → неделя точками (`WeekCaloriesCard`) → задачи, фото, план.

**Дневник питания** (`features/food-tracker`): заголовок «Питание» → дни
стрелками 44 px → вкладки подчёркиванием → итог дня фразой «Съедено N из M
ккал» + плитки остатка → лента приёмов пищи (время, точка, название
засечками, калории) → вода → панель быстрого ввода.

## 8. Правила для кода

Делать:
- брать роли: `bg-surface`, `text-fg-muted`, `border-line`, `bg-primary`;
- в SVG и графиках — `color.*` из `@burcev/design-tokens` или `chartTheme`;
- новое значение — сначала токен в `tokens/*.json`, затем `npm run tokens:build`
  и коммит вместе с `dist/`;
- новый повторяющийся элемент — компонент в `shared/components/ui` с тестом и
  примером на `/design-system`;
- тексты — через `t()`, ключи компонентов дизайн-системы — `ui.*`.

Не делать:
- классы палитры Tailwind (`text-gray-500`, `bg-blue-600`) и цвет литералом —
  ESLint не пропустит, а класс всё равно не сгенерируется;
- `dark:` для цвета — роль переключается сама;
- эмодзи как иконки — только `lucide-react`;
- перекрашивать показатель при превышении нормы;
- ставить вторую терракотовую кнопку на экран.

**Ветка, начатая до дизайн-системы**: после слияния с `dev` прогнать
`node apps/web/scripts/design-system-codemod.mjs` — он переводит классы
палитры в роли (`bg-gray-50 → bg-canvas`, `text-blue-600 → text-primary`,
`border-red-500 → border-danger`…), затем `npm run lint:web` покажет, что
механически не переводится.

## 9. iOS и Android

Источник — тот же DTCG JSON, развёрнутые значения обеих тем — в
`dist/tokens.json`. Когда стек выбран, к сборке добавляется вывод под платформу
(Style Dictionary читает DTCG напрямую):

| Токены | SwiftUI | Jetpack Compose | React Native |
|---|---|---|---|
| роли цвета | Asset Catalog с вариантами Any/Dark; `Color("fg")` | `lightColorScheme`/`darkColorScheme` + свои роли через `CompositionLocal` | объект темы + `useColorScheme()` |
| шкала текста | `Font.custom("Literata", size:, relativeTo:)` — Dynamic Type | `TextStyle` в `Typography`, размеры в `sp` | `StyleSheet` + `allowFontScaling` |
| отступы, радиусы | `CGFloat` константы | `Dp` | числа |
| цель нажатия | 44 pt (HIG) | 48 dp (Material) — берём 48 | 44 |

Платформенные условности, которые не переносятся из веба: нижняя навигация —
системная (`TabView` / `NavigationBar`), шторки — системные (`sheet` /
`ModalBottomSheet`), тактильная отдача на записи еды и выполнении цели.

## 10. Откуда решения

- **MacroFactor** — остаток по макросам в граммах как главный показатель; «сколько
  ещё можно» вместо процента.
- **Whoop** — запись в одно касание прямо с карточки; тёмная тема как
  полноправная, а не инвертированная.
- **Noom** — план дня как список действий с контекстом; куратор как голос
  продукта.
- **Yazio** — быстрый ввод (поиск, штрихкод, фото) без выбора приёма пищи.
- **Oura** — неделя как «сколько дней в норме», а не график двух линий.
- **Apple HIG / Material 3** — цели нажатия, семантические роли цвета, шкала
  текста, совместимая с системным масштабированием.
- **Подход к токенам** — как у Shopify Polaris, GitHub Primer и Atlassian
  (каталог [designsystems.one](https://www.designsystems.one/design-systems)):
  палитра → роли → компоненты, формат W3C Design Tokens, одна сборка на все
  платформы.
